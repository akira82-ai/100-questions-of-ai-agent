# Chapter 4 - Logs and Money in Practice

This is the chapter that turns a runnable DSH into a usable one: debugging with session logs, resuming and forking work, writing plugins, controlling context, and understanding cost. The command and pricing references below reflect the `0.1.0-rc.6` context from 2026-08-17. Re-check every number before using it in a decision.

## 43. How does the Session Log help me debug?

It turns debugging from guesswork into a scene reconstruction. Open the trajectory and inspect three things: the first point where behavior changed, the context injected immediately before it, and the tool result that followed. This separates a bad model decision from bad context or misleading tool data.

DSH's public postmortems use the same discipline. A postmortem is for a bug that escaped into a user, merged change, or release, especially when the escape reveals a mechanism or process gap rather than a typo. After a failure, open the trajectory before changing the configuration.

1) Session subsystem https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/session.md

2) Postmortem index https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/postmortem/README.md

## 44. Can I continue yesterday's session?

Yes. `resume` seeds a new lifecycle from the existing event log, restoring more than chat text: it preserves the semantic state of tools and context. The log marks which events came from the seed and which belong to the new lifecycle.

For long tasks, still write progress and important decisions to a file at stage boundaries. The log preserves process; files preserve deliverables. That handoff survives a restart and makes a later resume easier to verify.

1) Session subsystem https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/session.md

2) Anthropic on long-running agents https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents

## 45. What if a session goes off track and I want to try another path?

Use `fork`. It copies a trajectory at a chosen point, lets you experiment on a new branch, and leaves the original intact. The API has the source session, fork boundary, and child session ID; the boundary is the exact point where you want to try again.

The best workflow is `search` first, then `fork` from the failing step. Change one prompt or tool on the branch and compare the two trajectories. Do not delete the failed session: it is evidence about where the harness made the wrong choice.

1) Session subsystem https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/session.md

2) Official architecture documentation https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md

## 46. How can I see which tool the Agent called at each step?

Use `search` against the structured event stream. Search by a filename to find every tool that touched it, by a tool name to see how it was used, or by an error phrase to jump to the failure. File tools also return diffs, so the event contains what changed rather than only the fact that something changed.

The original, unparsed JSON parameters generated by the model are retained too. That makes questions such as "what did it actually pass to the tool?" answerable without rerunning the task. Tool, time, command, and changed file form the basic audit trail.

1) Session subsystem https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/session.md

## 47. Where should I start if I want to write a plugin?

Start with the official first-plugin tutorial and make it run in thirty minutes. A DSH plugin declares services, listens to events, and registers reversible side effects. Once that works, use the extension cookbook for recipes covering packages, tools, model adapters, and session nodes.

Set two acceptance conditions: the plugin appears in Settings, and unloading it leaves the runtime clean. If both pass, you understand the plugin contract; the rest is iteration.

1) First plugin tutorial https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cordis-tutorial/01-first-plugin.md

2) Extension cookbook https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/extension-cookbook.md

## 48. What are the easiest plugin mistakes to make?

Three are especially common: misspelling an event name, omitting an `inject` dependency, and writing an invalid schema. Compare event names character by character against the primer, list every service the plugin uses, and begin schema testing with the smallest valid input.

The official postmortem history includes an ACP server that crashed because an `export default` form lost its `inject` declaration. Dependency declarations are easy to overlook even for experienced maintainers, so make the pre-release check explicit.

```text
# Plugin release check
1. Compare every event name with the primer.
2. List every injected dependency and verify it is declared.
3. Run the schema with the smallest valid input before real data.
```

## 49. How do I stop DSH from overflowing the context?

Choose between automatic compaction for low effort and manual compaction for explicit control. Evaluate every strategy on three dimensions: trigger point, retained information, and continuity after recovery.

The compaction subsystem records a start event, writes the summary and replacement, and only then records completion. A crash leaves an unmatched lock that can be detected, rather than a false claim that compaction finished. Original events are not silently deleted; compaction is itself an event in the log.

For practical use, manually compact when a session has run long enough that it starts forgetting important facts. Configure automatic compaction for heavy workloads.

1) Compaction subsystem https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/compaction.md

2) Codex loop reference https://openai.com/index/unrolling-the-codex-agent-loop/

## 50. Why does someone else run the same task more cheaply?

Often because their harness manages context better, not because their model is cheaper. One comparison using the same model and 25 tasks showed more than a fourfold gap in cost per successful task.

| Harness | Passed | Median time | Tool calls | Cost per success |
|---|---:|---:|---:|---:|
| Oh My Pi | 22/25 | 231.7s | 248 | $0.52 |
| Kimi Code | 21/25 | 281.9s | 301 | $0.64 |
| Hermes Agent | 20/25 | 164.0s | 262 | $0.46 |
| Claude Code | 19/25 | 330.5s | 293 | $1.96 |
| Pi Agent | 18/25 | 156.2s | 223 | $0.57 |
| OpenCode | 18/25 | 270.5s | 299 | $0.72 |
| Grok Build | 18/25 | 196.2s | 402 | $0.66 |
| Codex | 17/25 | 233.4s | 297 | $0.66 |

More tool calls did not mean better results: Grok Build made 402 calls and passed 18 tasks, while Pi Agent made 223 and passed the same number. Start cost analysis with token flow, not model price.

```text
# Cost audit
1. Find the expensive step: repeated long context, raw large results, or all tools injected.
2. Externalize or summarize redundant information.
3. Track total cost divided by successful tasks.
```

## 51. How do I use peak and off-peak pricing without getting burned?

Put batch work in off-peak hours. The 2026-08-17 reference says peak hours are Beijing time 09:00-12:00 and 14:00-18:00; off-peak is the rest, including nights and weekends.

| Model | Period | Cache hit input | Cache miss input | Output |
|---|---|---:|---:|---:|
| V4-Flash | Peak | CNY 0.10 | CNY 3.0 | CNY 9.0 |
| V4-Flash | Off-peak | CNY 0.05 | CNY 1.5 | CNY 4.5 |
| V4-Pro | Peak | CNY 0.30 | CNY 9.0 | CNY 27.0 |
| V4-Pro | Off-peak | CNY 0.15 | CNY 4.5 | CNY 13.5 |

Interactive work belongs in the daytime. Batch processing, indexing, scheduled summaries, and non-urgent research belong in off-peak windows. Always verify current pricing instead of copying this table into production policy.

## 52. Why does cache hit rate matter so much?

Because the price difference can be thirtyfold. In the 2026-08-17 reference, V4-Flash input was CNY 0.10 for a peak cache hit and CNY 3.0 for a miss; V4-Pro used the same ratio at a higher absolute price.

A cache hit means the provider recognizes a stable context prefix. Keep stable instructions and tool definitions at the front, avoid changing configuration in the middle of a batch, and do not rebuild the whole prompt when only a small tail changed. Cache friendliness is a harness design decision, not a billing afterthought.

## 53. Can I trust the 88-page paper associated with DSH?

Trust it for architectural ideas, not as a promise that every implementation detail is stable. The paper explains Cordis and composability; it is a primary source for the design intent, while the live repository is the source of truth for current behavior.

Read the paper with two columns: principle and implementation. When the two differ, report the version and follow the code. A pre-release project can preserve its abstraction while changing names, configuration, and package boundaries.

1) Cordis paper repository https://github.com/cordiverse/paper

## 54. Which primary sources should I read first?

Do not start with social-media summaries. Read ten primary sources in four layers over two weeks: Anthropic's Building Effective Agents and OpenAI's practical agent guide first; then OpenAI's harness and Codex-loop articles, Anthropic's long-running harness article, and LangChain's anatomy; then Terminal-Bench, tau-bench, and the harness-disclosure paper; finally the DSH documentation for the exact version you use.

```text
# Two-week reading plan

        -> Unrolling the Codex agent loop
Week 2: Effective harnesses -> Anatomy -> tau-bench -> DSH documentation
```

## 55. How do I compare harnesses without mixing model and configuration differences?

Change one variable and disclose everything else. A comparison that cannot do both is entertainment, not a decision tool.

Disclose the task set and protocol, model and reasoning settings, tool set and versions, harness configuration, and cost definition. Composio's own comparison states that its best configuration used a different reasoning level and mostly official APIs. That caveat is exactly why other benchmark claims need careful reading.

```text
# Five disclosure fields
1. Task set and protocol
2. Model and reasoning configuration
3. Tools and versions
4. Harness configuration
5. Cost definition
```

1) Harness-disclosure paper https://arxiv.org/abs/2605.23950

2) DeepSeek benchmark notice https://api-docs.deepseek.com/zh-cn/news/news260813/

## 56. If I change only the harness, do success rate and cost really change?

Yes, and the spread can be large. In a mid-August 2026 comparison of 30 application tasks using DeepSeek V4-Flash, the best harness passed 20 tasks and the worst passed 14. Cost per successful task ranged from under three cents to nearly twenty cents.

The tasks were real operations such as email, GitHub, Slack, calendar, and Notion actions. A more expensive harness was not necessarily slower, and the top-ranked harness changed when the model changed. The stable conclusion is that harness differences are real; the exact ranking requires a controlled run because the published comparison included caveats.

1) Composio comparison https://composio.dev/content/best-ai-agent-harnesses

2) Harness-disclosure paper https://arxiv.org/abs/2605.23950

## 57. How should I read the DSH source code?

Follow two lines: the agent loop and the tool registry. First trace input assembly, model calls, tool execution, result injection, and the decision to continue. Then trace how tools are declared, mounted, and exposed to the model through Cordis services.

Read with a concrete question such as "How does Minimal end up with only two tools?" Follow the profile and patch until the answer is visible. The official guidance also recommends using an agent to explore the repository; a focused question gives both you and the agent a useful search target.

1) OpenAI loop anatomy https://openai.com/index/unrolling-the-codex-agent-loop/

2) DSH architecture https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md

Yes. The README says it plainly: `THERE WILL BE COMPATIBILITY-BREAKING CHANGES`.

The book's command baseline is `0.1.0-rc.6` from 2026-08-17; verify the current version before copying any command.
