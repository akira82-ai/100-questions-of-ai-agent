## 65. 考研/考公：怎么让 AI 基于我的笔记出模拟题和考点？

该做，但顺序不能反：自己先通读过一遍笔记，再让 AI 出题。空库让它出题，出来的就是网上随处可见的通用卷，跟你的薄弱点对不上。

一次只喂一章。把那一章的正文整段粘给 AI，要求它只用这段内容命题，并且出完追加一张缺口表：哪些考点你写到了定义层，哪些写到了能复述推导，哪些只抄了个标题。这张表比题目本身值钱，它直接告诉你今晚补哪一节。做完的题别丢，错的那几道回填进原笔记，下一轮出题它们就是新的重点。

用双链把公式和推导连成网，命题时让 AI 沿链条跨节出综合题，比按章刷题更接近真实卷面。不想从空库搭起，社区有现成学生向示例库，clone 下来改比从零快得多。考前别再开新坑，用同一份缺口表滚动复习，比换新资料更稳。

```
# 基于我的笔记出模拟题（把 [[第X章笔记]] 换成你的文件名）
只读 [[第X章笔记]] 的正文，不要引入笔记以外的知识，按三档命题：
- 选择题 10 道：只考我标过「重点」「易错」的概念
- 简答题 5 道：只考我写下的推导步骤或流程
- 论述题 2 道：必须串起本篇里双链指向的其他笔记
出完追加一张缺口表，三列：考点 | 我写到了第几层（标题/定义/推导） | 缺什么
我笔记里没有的考点，标「本篇未覆盖」，不要替我补写答案。
```

## 66. 背了就忘，用 AI 把笔记变闪卡（Anki 式）怎么搞？

先定落点再动手：要跨设备刷、要看遗忘曲线统计，走 Anki；只想留在库里、不愿再开一个软件，装 Spaced Repetition 插件在笔记里直接标卡。两边同时开就是双份维护，选一个。

只切最薄弱的那一章，跑通导入再扩。让 AI 读你的笔记正文，切成一问一答，你审一遍删掉牵强的，再批量导入。导 Anki 的关键在字段顺序固定为 `正面,背面,标签`，顺序对了，映射就不用每次手调。

卡片来自你自己记的东西，考的就是你真实的薄弱点。审卡这步别省，AI 切错的问题留在牌组里，会一直错着背下去。导完先刷二十张确认映射没错位，再批量补剩余章节。

## 67. 写作卡壳时，怎么让 AI 从我 vault 挖选题和素材？

卡壳时先让 AI 做检索，别让它替你写正文。它一动笔，你就会顺着它的句子往下滑，写出来的东西没了你的语气。

具体动作是让它输出一张三列表：可用素材、出自哪篇笔记、能接到你正在写的哪一段。分三组捞：能直接复用的设定和场景、半年前记过但你现在想不起来的相似段落、互相矛盾的两条记录。第三组最值钱，矛盾点天然是冲突的种子。

写长篇时把每个场景拆成独立文件，用 Longform 排序和拼稿，卡在某一场就只打捞那一场的素材，不用整库翻。捞上来的东西你自己筛，用三成就够破局，剩下的留在池子里。定稿前把这组三列表贴在文档开头，写的时候随手对照，不用来回翻旧笔记。

```
# 卡壳时的素材打捞（只检索，不写正文）
检索我 vault 里所有提到[角色 / 主题]的笔记，输出三列表：
可用素材 | 出自哪篇笔记 | 能接到我正在写的哪一段
分三组给我：
A 可直接复用的设定、场景、对白
B 我半年前记过、现在没想起来的相似段落
C 互相矛盾的两条记录（这类最容易写出冲突）
只做打捞和归类，一句正文都不要替我写。
```

依赖：Longform 插件（长稿按场景拆分与拼稿）

资源：Longform https://community.obsidian.md/plugins/longform

## 68. 写了一半的文章，让 AI 接着写会不会跑偏？怎么控？

会跑，而且默认它一定跑。它看不到你脑子里那个结论，只能顺着上一句的语感往前滑。控制办法只有一条：先出提纲后动笔，一次只放一段的缰绳。

三步走。第一步禁止它写正文，只列接下来三段的提纲，每段一句话，标明各自要解决什么问题；你改完提纲它才能动。第二步只写第一段，限字数，要求沿用你已写部分的人称、时态和用词习惯，不许引入你没写过的事实和数据。第三步让它把新写的和你的原文并排比对，指出语气断裂的地方，你点头再写下一段。

改写时用插件的选中改写模式，只替换选中那几句，别让它整篇覆盖。顺手把文件恢复打开，改崩了能翻回半小时前的版本。

```
# 让 AI 接着写而不跑偏（三步，缰绳一次只放一段）
第一步（先不写正文）：
读我已写的部分，列接下来 3 段的提纲，每段一句话，标明各自解决什么问题。
第二步（我改完提纲后）：
只写第 1 段，200 字以内，沿用我已写部分的人称、时态和用词习惯。
不许引入我没写过的事实、数据、案例。
第三步：
把这段和我的原文并排比对，列出语气或用词断裂的地方，等我确认再写下一段。
```

依赖：Copilot 插件（用选中改写，别整篇替换）

## 69. 自媒体日更没货，AI 怎么从旧笔记生成 30 个选题？

选题荒多半是检索问题，你库里的碎片够写三个月，只是散着找不到。先用搜索把范围框出来，再让 AI 聚类，顺序反了就会得到一堆你写不动的空题。

框范围用内置搜索语法，`path:` 限目录、`tag:` 限主题、前面加减号做排除，一条搜索就能把近三个月的日记捞干净。把结果正文粘给 AI，要求每个选题至少合并两条以上碎片，单条撑不起的直接不列，这一条能砍掉八成水题。

选题清单出来后先挑五六个立刻能写的，其余存进选题池，下个月再扫一遍。挑的标准是素材厚度，不是标题听起来有多响。每月底把选题池扫一遍，旧碎片攒够了就自动变成新选题，不用硬想。

```
# 第一步：在 Obsidian 搜索栏框范围（直接粘）
path:"daily/" -tag:#归档
```

```
# 第二步：把搜到的正文粘给 AI，用这段
把这些碎片按主题聚类，输出 30 个选题，每行一个，格式：
选题标题 | 一句话切入角度 | 用到我哪几条碎片
要求：
1. 每个选题至少合并我 2 条以上碎片，单条撑不起的不要列
2. 标出哪 5 个我素材最厚、明天就能写
3. 通用鸡汤题、我库里没素材的题一律不要
```

## 70. 读论文/报告，怎么让 AI 摘要并自动连到我已有笔记？

摘要本身不值钱，值钱的是挂进你已有网络那一步。只要摘要不出现一条双链，这篇论文读完就是孤岛，三个月后你连读过都不记得。

做法是固定一套文献笔记模板，把"与我已有笔记的关系"做成必填项，且分三类：支持、冲突、补白。要求 AI 每篇至少给三条关系，每条写清属于哪一类和一句理由。关键一步是把你的笔记标题清单一并粘过去，明确告诉它双链只能从清单里选，找不到就写"暂无对应笔记"，这样它编不出不存在的文件名。

从文献管理软件一键生成带元数据的笔记，年份、作者、条目链接自动填好，你只写判断那一栏。

```
---
type: literature
title:
authors:
year:
zotero:
读于:
---
## 一句话结论
## 问题 / 方法 / 结论 / 局限
## 与我已有笔记的关系
- 支持：[[ ]] 理由：
- 冲突：[[ ]] 理由：
- 补白：[[ ]] 理由：
## 我自己的判断
```

## 71. 研究者：怎么用本地 AI 精读文献又不泄密？

涉密或未发表的文献只走本地模型，这条没有折中。硬件不够就换更小的模型，别换成云端。慢一点读得完，传出去一次就收不回来。

在设置里填了本地地址不等于万事大吉，多数泄露就出在没验证过它到底走没走网。装完模型、在插件里配好本地地址之后，做一次断网测试：关掉 Wi-Fi 再问一次，能正常回答才说明全程在本机。原始涉密文件放加密盘，用完就卸载，库里只留脱敏后的笔记。

7B 级模型做摘要、提观点、找矛盾点够用；需要长文档跨页推理时再上更大的模型，代价是等待时间明显变长。同一台机器上把涉密和公开两套模型分清楚，别让公开模型偷偷读到加密盘。两个模型共用一个 Obsidian 时，更得在插件里把目录权限划清。

```
# 1. 装模型（终端）
ollama pull qwen2.5:7b
ollama serve

# 2. Obsidian → Copilot 设置 → Model → Add Custom Model
#    Provider:   openai-format
#    Base URL:   http://localhost:11434/v1
#    Model Name: qwen2.5:7b
#    API Key:    随便填一个非空字符串（本地服务不校验）

# 3. 断网验证：关 Wi-Fi 再问一次，能答 = 全程本地

# 4. 原始涉密文件放加密盘，用完卸载，vault 里只留脱敏笔记
```

依赖：Ollama + Copilot 插件

资源：Ollama https://ollama.com/ · Copilot for Obsidian https://community.obsidian.md/plugins/copilot

## 72. 职场人：会议记录怎么让 AI 沉淀成可检索行动项？

纪要写得再漂亮，行动项查不出来就等于存档。判断很简单：行动项必须用统一的任务格式写，带负责人和截止日期，能被查询语句捞出来，其余段落都是背景。

会中你只管手记真实要点，别录了音就等 AI 全包。会后把散记粘给 AI，让它按四段结构整理，行动项每条必须齐三样：做什么、谁做、截止日期，缺哪样写"待确认"，不许它猜。然后在项目主页放一个任务查询块，所有会议的未完成项自动汇到一处，周会前扫一眼就知道谁欠什么。

真正省时间的是格式统一这件事，跟用哪个 AI 关系不大。日期格式、标签命名先定死，查询才捞得全。模板建一次，之后每次开会只填四段，行动项自然就能被捞出来。

## 73. 客户/项目资料太多，AI 怎么帮我在需要时浮现对的那个？

客户一多，靠文件夹找资料一定会输。改成语义浮现：写 A 客户方案时，侧栏自动列出你记过的 A 客户偏好、上次踩的坑、相似项目的打法。

装完插件觉得浮现不准，原因几乎都在笔记本身。向量检索吃的是文字，客户笔记只有一行"下周跟进"，它没东西可捞。改法是每篇客户笔记开头写两三句白话概括，把行业、诉求、当前阶段说清楚，浮现质量立刻不一样。新签客户手动连一条相似项目的双链，等于给它一个起点。

模板里的"对方原话摘录"这一栏别省。原话里的措辞是最好的检索锚点，转述过的句子会丢掉那些关键词。浮现质量差先回头改笔记开头那几句概括，别急着换插件或调参数。

## 74. 写方案/汇报，AI 怎么基于我的历史材料起草不瞎编？

防瞎编只有一招：强制每段带出处，没出处的段落一律删掉。指望靠提示词让它"别编"没用，得让编造在版面上暴露出来。

具体做法是给它一份封闭的材料清单，明确说只能用清单里的内容，每段末尾用行内字段标出依据，例如 `[来源:: [[三月客户沟通纪要]]]`。缺材料的地方不许用常识补，整段写成"【缺材料】需要补充：..."。你扫一遍初稿，凡是没有来源标记的段落直接删，剩下的才是有据可查的部分。

"为什么选这个方向"这一节留空，你自己写。这是方案里唯一真正需要你署名的地方，其余排版、罗列、措辞都可以让它先干。材料清单随方案一起存进笔记，下次改稿直接复用，不用重新翻聊天记录。

## 75. 法务/医疗等敏感行业，AI 怎么用才不踩合规红线？

三条硬线：本地模型、静态加密、最小权限。任何一条守不住，这批资料就别接 AI。这行的账算法跟别的行业不同，快十分钟没有价值，泄一次就是事故。

落地靠分区，靠自觉守不住。库里分三色目录：红区放原始涉密材料，挂在加密盘上，AI 插件的排除目录里把它填进去；琥珀区放脱敏后的工作笔记，只走本地模型；绿区放法条、公开判例、行业公开资料，可以走云端。脱敏用一张固定的替换表，同一个当事人在所有笔记里用同一个代号，否则交叉比对还是能还原。

上传前过一遍四问，任一为否就停手。麻烦，但比事后解释便宜得多。分区目录建好后，所有新笔记先归区再写，别等出事才补分类。

## 76. 做复盘：怎么让 AI 把一年笔记合成"我今年成长了什么"？

年底才想起复盘就晚了。年度复盘的质量取决于全年周记的密度，没有周记，AI 只能从零散日记里给你熬一锅漂亮的空话。

先用周期笔记插件把周记跑起来，模板固定四栏：这周完成了什么、最大收获、哪里做得不好、下周三件事。收获那栏强制写清为什么算收获，一年后你才看得懂当时在想什么。年底把 52 篇周记正文一次性粘给 AI，要求它按季度提炼四件事，每条必须引具体日期：真正做完的（有产出物才算）、反复卡住的同一类问题（出现三次以上才列）、关注点的迁移、说了要做但全年没动的。

复盘里最该盯的是第四条（说了要做但全年没动的事），也正是这条最有用。明确禁止它下"你成长了"这类结论，只摆事实和日期，结论你自己下。

```
## 这周完成了什么
## 这周最大收获（写清为什么算收获）
## 哪里做得不好
## 下周最重要的 3 件事
## 关键词：#领域/ #项目/
```

```
# 年度合成提示词（把 52 篇周记正文一次性粘进去）
按季度提炼四件事，每条必须引用具体周记的日期：
1. 我真正做完的事（有产出物的才算）
2. 反复卡住的同一类问题（出现 3 次以上才列）
3. 关注点的迁移（Q1 在写什么，Q4 在写什么）
4. 说了要做但全年没动的事
不要下「你成长了」这类结论，只摆事实和日期，结论我自己下。
```

## 77. 读书博主：怎么用 AI 把书摘变成可引用的知识卡片？

整本书的读书笔记没法引用，一卡一概念才能引用。拆卡这一步别省，它决定了这本书半年后还能不能被你调出来用。

流程是两段。读完先用固定模板记一篇整书笔记，frontmatter 写清书名、作者、评分、读完日期，正文四栏：一句话总结、核心观点、启发与行动、金句摘录。然后让 AI 把这篇拆成若干张卡片，每张一个概念，格式统一为概念名、一句话定义、大白话解释、一个你这行用得上的例子、出处到章。拆不出独立概念的段落直接丢，宁可少出卡。

卡片攒起来之后，用一个查询块把全部读书笔记按读完日期列成书单，写长文时按标签翻卡，卡片就是砖。想看成型的结构长什么样，社区示例库里有现成的一卡一概念加查询汇总的搭法。

```
---
tags: 读书笔记
书名:
作者:
评分:
读完日期:
---
## 一句话总结
## 核心观点
## 启发与行动
## 金句摘录
```

```
# 提示词：把整书笔记拆成可引用的卡片
```

## 78. 学外语：AI 怎么基于我的笔记做情境化练习？

通用题库练不到你的薄弱点。先建错词表，再谈练习，顺序反了就是在陪课本刷题。

错词表按下面这张表填，字段一个都别减："我写成了"那一列是全表最有用的，它保留了你出错的原始形态，AI 靠它才能出到点上的改错题。表存成一篇文件，每周一篇，放在同一个目录下。

要跨周汇总复习就得注意：查询插件读不到 Markdown 表格里的单元格，所以每条错词同时写一行带行内字段的任务行，用一个查询块把所有未掌握的按错次排序捞到一处，每周复习就看这一屏。练习环节把错词表整张粘给 AI，要求只用表里的词出题，出三样：情境对话、改错题、小作文题。写完让它只针对表里记过的错因给反馈，别顺手改你其他表达，那样反馈会散掉。

```
---
type: 错词表
语言: 英语
周次: 2026-W33
更新: 2026-08-10
---

| 词条 | 我写成了 | 正确说法 | 错因 | 出错场景 | 首错日期 | 错次 | 已掌握 |
|---|---|---|---|---|---|---|---|
| effect / affect | affect the effect | the effect of the change | 词性混淆 | 工作邮件 | 2026-07-02 | 3 | 否 |
| bring / take | bring it there | take it there | 方向相反 | 口语对话 | 2026-07-18 | 2 | 否 |
| in / on time | I arrived on time barely | I barely arrived in time | 搭配固定 | 口语对话 | 2026-08-05 | 1 | 否 |
```

## 79. 创业/副业：怎么用 vault+AI 管想法，不丢灵感？

## 80. 内容老重复自己？AI 怎么提示"你三年前写过类似观点"？

写之前先查重，比发出去被读者指出来强。这件事花两分钟，能省掉一整篇白写的稿。

动作是三步。新建笔记时先把这次要说的核心观点写成一句话，写观点而非标题，语义检索才咬得住。打开插件侧栏看它浮出的前五篇，逐篇问自己一个问题：这次比它多了什么。答不上来，这篇就别写了。

浮出来之后别只看有没有重复，让 AI 出一张比对表，判定只能三选一：重复、升级、转向。判"升级"就说明新增了什么，判"转向"就说明立场变在哪，并各给一句能直接放进开头的自引句。承认自己改过主意，比假装第一次想到这件事更有说服力，读者也顺带看到了你的思路怎么变的。

```
# 开写前 2 分钟查重
1. 新建笔记，先把这次要说的核心观点写成一句话（写观点，别写标题）
2. 打开 Smart Connections 侧栏，看它浮出的前 5 篇
3. 逐篇问自己：这次比它多了什么？答不上来就别写这篇
```

```
# 提示词：比对这次和过去写过的
这是我这次的观点：<一句话>
这是侧栏浮出的 5 篇旧笔记正文：<粘正文>
输出一张表：旧笔记 | 当时的说法 | 这次的说法 | 差在哪 | 判定
判定三选一：重复（建议弃稿）｜升级（写明新增了什么）｜转向（写明立场变在哪）
判「升级」或「转向」的，各给一句能直接放进开头的自引句，
例如「三年前我认为 X，现在我改了，因为 Y」。
```

## 81. 跨部门协作资料散，个人 vault+AI 能补位吗？边界在哪？

能补你自己经手的那一半，补不了别人手里那一半。想用个人库替代团队协作系统，第一次权限纠纷就会把你打回来。

边界画在收纳环节，画在事前。三条线记住：自己写的会议纪要、自己经手项目的过程记录、公开资料的读书笔记，随便进；含他人个人信息、客户名、未公开财务数字的，打码再进；别人保管的原始文件、需要授权才能看的系统导出、他人聊天记录，永远不进。这三条守住，个人库就只有你自己的积累，AI 读它没有合规风险。

同事要信息时，给结论和出处，别转发原始文件。真需要多人共同维护的内容，走团队工具或者官方的共享保险库功能，权限和审计留在有记录的地方。个人库只装自己经手的东西，协作的事交给有权限记录的团队系统。

```
# 个人 vault 的三条收纳边界
可以进：我自己写的会议纪要、我经手项目的过程记录、公开资料的读书笔记
打码进：含他人个人信息、客户名、未公开财务数字的内容
永不进：别人保管的原始文件、需授权才能看的系统导出、他人聊天记录

# 同事要资料时，用这句回复（给结论和出处，不转发文件）
「我这边的记录是 X，来自 <日期> 那次会议。
 原始文件在 <团队系统> 里，你按权限自己取一份，我不外发。」
```

## 82. 一个真实工作流示范：从收藏到产出，AI 在哪几步替我干活？

整条流里 AI 只该干四件体力活：归类、标来源、浮现、出草稿。判断、定方向、定稿留给你。想清楚这条分工，剩下的只是把目录建好。

库分三层。`raw/` 放浏览器剪藏的原文，保留来源链接，一个字都不加工；`wiki/` 放加工过的概念页，每页顶部注明来源，里面留一份 `index.md` 当总目录；`drafts/` 放成稿。你每天只做一件事：看到有用的东西一键剪进 `raw/`，不追求当场消化。

每周跑一次编译：让 AI 读 `raw/` 里新增的文件，每篇生成一页来源摘要，抽出概念补进已有概念页或新建，最后更新总目录。要写东西时让它先读总目录再起草，每个论点后面标出依据的概念页，没依据的写"【待补】"，结论段留空。你干的是丢真实想法、审归类、定结论、改定稿这四件，其余交出去。

```
vault/
├─ raw/       浏览器剪藏的原文，保留 source_url，不加工
├─ wiki/      加工过的概念页，每页顶部注明来源
│  └─ index.md   总目录，AI 每次先读它
└─ drafts/    成稿
```

```
# 每周一次：把 raw/ 编译进 wiki/
读 raw/ 里 <日期> 之后新增的文件：
1. 每篇生成一页来源摘要，保留 source_url 和剪藏日期
2. 抽出其中的概念，已有概念页就补充，没有的新建到 wiki/concepts/
3. 更新 wiki/index.md，标出这周新增了哪几页
原文里没有的观点不要写进 wiki/，需要我判断的地方留 TODO。

# 要写东西时：起草
先读 wiki/index.md，再基于 wiki/ 起草[主题]初稿。
每个论点后面用 [来源:: [[概念页]]] 标出依据，没依据的写「【待补】」。
结论段留空，我自己写。
```
