# 第一章 · 上手不劝退：最小可行 Obsidian+AI

你有没有过这种时刻：和 AI 聊了一晚上，灵感哗哗往外冒，关掉窗口的瞬间，那些话就像没发生过。第二天想找回来，只记得昨天好像聊了个厉害的东西，具体内容全没了。

又或者：微信收藏里躺着八十多篇以后一定看，半年没点开过一篇。你不是忘了，是根本想不起来自己存过。

再或者：换了个新项目，AI 不认得你上季度写过的东西，你又得从零把背景讲一遍。你开始怀疑，到底是自己记性差，还是这工具本来就不记得你。

这不是你的问题，AI 每次都从空白开始，它不认识你。你越依赖它，越需要有个地方把你自己接住。这个地方，就是你的 Obsidian vault。把对话落进自己的 vault，AI 才接得上你的上下文，而不是每次都从空白开始。

那如果把这个地方用起来，会发生什么？给你三个真实发生的画面：把读书划线、日记碎片、目标清单、日程全部攒进一个本地 vault，换到任何新项目，AI 都能秒回你上季度的背景，写作和决策不再从空白开始；每天醒来收到一屏简报，天气、昨日进展、待办截止日全齐，AI 还从你的双链网络里揪出你自己都没注意到的隐藏模式，比如某类目标总在季末卡住；从付费云端工具迁回本地 Obsidian，让 AI 第一次读得懂你攒了多年的灵感，语音闪念上车就能记、推文视频直接入库。

这本书适合想让每天的输入变成积累和输出的人，也适合愿意在记的时候做一点点手动标注的人。它不适合追求零手动全自动的人，不适合把 AI 当替你思考的人，也不适合需要一整个团队共用一个知识库的人。如果你属于后面这几类，前面的玩法可能让你失望。

## 1. 天天用 AI 聊完就忘，我是不是白聊了？先戳破这句话，再动手

没白聊，但聊完不落笔，这事儿基本就等于白聊。你最有价值的那点思考会全部蒸发在聊天记录里，最后剩下一个只进不出的文件堆。

管用的做法是给自己立一条硬规矩，每次问答要两样东西，答案本身，外加一条落进笔记的更新，哪怕只是往某个页面追加两行。这条得写死，不能二选一，一留余地回流立马就停。复利来自回流，回流靠的是强制，靠自觉撑不了两周。

落到哪儿倒不用纠结，先把两层分开就行。原始的对话记录、剪藏、文章，扔进一个只新增不乱改的地方，它不负责漂亮，只负责保留原始证据。问答得出的结论、对比、报告，落到另一个地方，那是你的工作台。临时冒出来的想法可以先记手机备忘录，真正值得沉淀的再往库里搬，捕捉和沉淀各干各的，别指望一个地方全包。

还有一点得先打个预防针，别一上来就花好几周搭结构。系统建得再漂亮，日子没变化，那只是把拖延包装成了效率，最后你收获一个整理得特别整齐的墓地。先让东西进来，结构以后自己会长。

可复制模板（直接复制使用）：

```
vault 根目录下先建两个文件夹：

raw/        原始对话、剪藏、文章，只新增，不乱改
outputs/    问答结论、对比、报告

再把这条规矩写进你和 AI 的规则文件（CLAUDE.md 或 AGENTS.md）：

每次回答问题，同时给两样东西：
1. 答案本身
2. 一条笔记更新，哪怕只往相关页面追加两行
两者不能二选一。
```

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 2. 我把微信收藏当第二大脑，为什么总想不起来用？

因为收藏那一刻基本就等于埋葬，你存的时候想的是回头再看，回头这事儿一次都没发生过。真要用了再去翻，翻上半小时也未必找得出来，那地方搜不到、连不起来，也压根不归你。

搬是要搬，但别想着全量搬。挑那些以后还会继续查找、继续补充、继续用的内容进 vault，纯粹为了存着安心的那些放掉，记下来也只是换个地方囤着。老库迁移更要认这个账，八成成功就算赢，新东西先走新结构，旧的慢慢消化，一次性大扫除没点干劲根本干不完。

搬的时候要把手动那几步的成本压下去。复制、清格式、配标题，一套下来好几分钟，一忙就跳过，跳过几回这习惯就废了。批量的直接用 Importer 导，零散的顺手一句话交代清楚来源和你为什么存它，这一句决定了以后你和 AI 还能不能把它捞回来。

让库真正活起来的是用的那一下。每次调出一篇旧笔记，顺手补一点新信息进去，这比攒着不动强得多，也比哪天下决心从头整理一遍靠谱。

资源：Obsidian Importer https://obsidian.md/plugins?id=importer

## 3. 都说 AI 越强越不用记笔记，这话到底坑在哪？

坑在 AI 没有立场、没有经历、也没有审美，你不给它喂东西，它回你的永远是通用、平均、谁都写得出来的那一版。同样的模型，喂进去你自己的素材、方法论、经历和判断，输出的才是带你印记的东西。

所以记笔记这件事没被 AI 干掉，它只是换了个身份，从存档变成了原料。记的时候按一条规矩来就行，默认三个月后的自己完全忘了当时的上下文，把关键细节、背景、逻辑都补进去，这一篇同时写给未来的你和读你库的那个 AI。资料格式稳定、路径清楚、不散落在几十个聊天窗口里，它下次才接得上。

另一头的坑更隐蔽。想把记住这件事整个外包出去，你会连反思一起外包掉，不再重新审视想法，不再质询它们，归档完就信任那个结构，然后就没有然后了。学习本来发生在外部动作引发内部加工的那一刻，把新信息跟已有知识连起来就是这类动作，让 AI 代劳等于绕开了技能发展本身。别把理解外包出去，这句话在这儿是硬的。

落地就一步，聊完 AI 挑一个你最认同的结论，用自己的话写进 vault，背景、结论、下一步各一行。背景喂准了，它才从还行变成真帮得上。

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 4. 想让 AI 帮我记，先想清"记给未来的我"还是"记给 AI"？

先写给人，写给人的那一版 AI 也读得懂，反过来不成立。原封不动复制粘贴等于零，用你自己的话重新表达出来，这一篇才开始有价值。

一篇以后还能复用的笔记，不该只有搬过来的原文，四块凑齐就够用：这是什么，用自己的话概括一遍；我的判断，为什么它值得留下；下一步，准备拿它做什么；相关内容，链到哪些项目或主题上去。在相关内容里写一个双链，以后从这篇能点进主题页，主题页的反向链接里也能重新看到它。

给机器读的那层，加几个字段就行。标题用日期加场景加主题，别叫新笔记、随笔这种模糊名字。开篇第一句直接说清这篇解决什么问题，AI 靠它判断相关性。来源链接、作者、时间原样留着，以后好溯源。字段千万别贪多，太多最后没人维护，先固定 updated、status、summary、source 这几个真会用到的，再按需要加。

顺序别搞反了。你先把想法落下来，AI 才有东西可读、可连；甩给它一堆没有你标注的原材料，它产出的也只是没根的碎片。

可复制模板（直接复制使用）：

```
---
created: 2026-07-31
updated: 2026-07-31
status: active
summary: 这篇笔记主要解决什么问题
source: 原始来源或链接
---

## 这是什么
用自己的话概括

## 我的判断
为什么值得留下

## 下一步
准备拿它做什么

## 相关内容
- [[某个项目或主题]]
```

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 5. 我笔记很少，现在开始用 Obsidian 会不会太早？

一点不早，从空库起步、零插件零 starter kit 反而是更好的开局，你没有历史包袱要清。

第一次用它确实可能还不如备忘录方便，这很正常，它不是下载完就有用的软件，得你按自己的实际情况一点点把真实内容放进去。笔记慢慢变多，关系慢慢建立，那张星图一样的关系图才会自然长出来。一周写十篇可能没什么感觉，一个月、三个月之后才是它兑现价值的时候，用满半年，你会拿到一个别人复制不走的东西。

别追求完美的笔记，一行字也值得记，它是给自己用的，不是作品。先写再整理，别先花两小时设计文件夹分类，写多了自然知道该怎么整理。同一种笔记反复出现，再去做模板；同一个手工动作反复发生，再去找插件。插件是用来减少已经确认的重复劳动的，不是给一个还没成形的习惯提前加维护成本。

手上有旧笔记也别急着全搬。先把重要的复制过来，剩下的等真用到那天再带过去，一次性大爆炸式迁移最容易把人干趴下。

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 6. 第一次打开 Obsidian，我只该做哪三件事？多一件都是负担

建一个仓库、留一个收件箱、写第一篇日记，插件、双链、关系图谱全放一边。

仓库就是电脑上一个普通文件夹，名字随便取，位置放桌面或文档，别塞进 C 盘深处。想要中文界面就去设置里 About 那一栏，Language 选简体中文，重启一下。收件箱是个文件夹，以后所有临时素材先丢这里，顺手把设置里的新建笔记存放位置指到它，不然笔记会到处乱跑。日记在核心插件里开一下就能用，每天一篇，命名 YYYY-MM-DD。

第一天不要碰社区插件。核心插件里先把日记、大纲、书签、标签、模板这几个开起来，等用了一两周，发现原生真满足不了某个需求，再去搜对应的插件。装得多不等于用得好。装了二三十个插件，每个只浅浅试一下，结果启动变慢、界面变复杂、大部分根本没用上。顺带说一句，你库里几千篇 md 都不会让它卡，拖慢它的通常是插件。

有两个快捷键值得当天就练成肌肉记忆，Ctrl/Cmd + P 是命令面板，任何功能找不到就在这儿搜；Ctrl/Cmd + O 是快速切换，输入笔记名秒开，比用鼠标翻文件夹快太多。

可复制模板（直接复制使用）：

```
我的仓库/
├── 00-收件箱/   # 临时素材，待整理
├── 01-日记/     # 按 YYYY-MM-DD 命名
├── 03-项目/     # 正在做的事
├── 05-资源/     # 读书 / 知识卡片
└── 99-附件/     # 图片 PDF
```

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 7. 别人的完美 vault 截图看多了更焦虑，我该怎么脱敏？

照搬别人那套复杂 vault，等于逼着自己去做一件本来不属于你的事。

那些 power user 晒出来的 setup，扒开看多半是几十个插件加一篇三页长的日记，底下再分出几十个子页记生活里的鸡毛蒜皮，那是通往倦怠的配方，不是你的及格线。更要命的是，那些截图卖的往往就是他们自己的用法，你看着看着就把自己的用途改成了别人的用途，而没去把工具改成适合自己的。本来只想找个地方写日记，跟着教程走一圈，回头发现自己在搭媒体库和知识图谱，日记倒是一篇没写。

教程本身也是坑，好的教程照样会给你触发一轮新的改动，改完不见得留得下来，过阵子刷到另一个又想推翻重来。规矩自己定，定完写下来，做一份属于你的风格手册。一致性能把几百个未来的决定折叠成一个，比如标签一律用复数，你就再也不用纠结新标签该怎么命名，想改随时能改。

复杂度只在你真撞上一个具体障碍、它明确挡着你用的时候才加，不要提前演练。手痒想试别人那套方法论，开一个一次性的 dummy vault 去试，别拿主库当试验田。

资源：Obsidian 官方站点 https://obsidian.md/

## 8. 本地 Markdown 到底好在哪，为什么不怕软件倒闭？

因为你的笔记就是硬盘上一堆 .md 纯文本，没有数据库，没有专有格式，Obsidian 这家公司哪天没了，记事本照样打得开。

云端笔记工具的坑在数据绑架。私有格式导出来的东西要么是 HTML，要么是带一堆样式的富文本，压根不是标准 Markdown，你想走都走不干净。纯文本反过来，想让你写的东西在 2060 年的电脑上还读得开，关键是它得能在 1960 年的电脑上读得开。app 都是速朽的，文件才有机会留下来。

这事在 AI 时代还多一层好处。所有 AI 工具都能直接读 Markdown，不用导出、不用转换、不用上传，那堆 .md 就摆在本地，给个访问权限它就能读、能检索、能接着往下写。你也可以随时换模型、用 Git 做版本管控，或者干脆本地跑一个模型，数据一步都不出门。

有一点别搞混，本地有文件不等于已经备份。硬盘坏了、手滑删了，一样全没。同步解决的是手机和电脑看到同一份，备份解决的是删错了能不能捞回来，两件事分开办，别指望一个顶俩。

可复制模板（直接复制使用）：

```
# 一级标题  ## 二级  ### 三级
**加粗** *斜体*
- 无序  /  1. 有序
- [ ] 待办  - [x] 已完成
> 引用
[[内部双链]]  [[内部双链|显示文字]]
```

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 9. 手机和电脑怎么同步笔记最省事？别一上来就折腾插件

新手从轻量方案起步就行，官方 Sync、iCloud、坚果云挑一个，Git 和自建那一堆等你被真正的痛点卡住了再说。

官方 Sync 是端到端加密，全平台原生支持包括 iOS，秒级实时，自带版本历史和冲突解决，出了问题官方替你排查。缺点就一个，贵，标准版 4 美元一个月给一个库一 GB，Plus 版 8 美元一个月给十个库十 GB。想省钱就把 vault 直接丢进系统云盘的同步目录，让云盘客户端自己在设备之间搬文件，Obsidian 这边压根不管同步这码事，零插件。

网盘这条路有几个坑得先知道。iCloud 在 Windows 上会导致文件重复或损坏，千万别碰；OneDrive 得把 vault 文件夹标成始终保留在此设备上，同时关掉文件按需，否则 Obsidian 会以为文件丢了；三种网盘共同的毛病是延迟几秒到几十秒，不实时，而且 .obsidian 目录里散着一大堆小文件，网盘客户端经常在这儿卡住。也别同时用两个云盘同步同一个文件夹，冲突是必然的。

还有两条原则跟方案无关。多端同时改必然产生冲突文件，任何方案都治不了，得养成一端写完再切另一端的习惯。再好的同步也不等于备份，删除和损坏会被忠实地复制到所有设备上，单独留一份备份是必须的。

资源：Obsidian Sync https://obsidian.md/sync

## 10. 文件夹和双链到底选哪个？给一个不纠结的判断法

不用二选一，文件夹告诉你东西存在哪里，链接和反向链接告诉你它跟什么有关，管的压根是两码事。

文件夹保持浅层，一到两级封顶，别花几小时设计完美分类，没写过几篇就开始设计分类，必翻车。链接也不用为了让关系图好看硬加，只有当两篇之间真的存在来源、延伸、属于同一项目、支持或反驳这类关系时，才把它们连起来。同主题的笔记攒到一定量，做一张 MOC 目录笔记把它们串到一块，比建一堆嵌套子文件夹好使得多。

两个极端都行得通，而且都活得挺好。一类人几乎不用文件夹，理由是很多笔记同时属于好几个领域，他不想每次都花脑子想这篇该放哪；另一类是彻底的文件夹派，文件不归进文件夹脑子就要融化，链接一个都不用。你不用站队，选让自己舒服的那种。

真要一个判断法，那就是先写半个月，看哪种需求自然冒出来再动手，MOC、PARA、卡片盒三种混着用完全没问题。

可复制模板（直接复制使用）：

```
# 文件夹 vs 双链 判断法
- 它存在哪里 → 文件夹（浅层，1-2 级封顶）
- 它和什么有关 → [[双链]]（有来源/延伸/同项目/支持或反驳关系才连）
- 同主题笔记攒多了 → 建一张 MOC 目录笔记串起来
- 拿不准的 → 先丢 00-收件箱，写半个月再说
```

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 11. 不装任何 AI 插件，纯 Obsidian 先跑一周有用吗？

有用，而且建议你就这么干，新手期先裸用一两周，插件的事往后排。

Obsidian 不是下载完就自动有用的软件，你得先按自己的实际情况把真实内容放进去。这一周只做一件小事，把每天冒出来的想法、跟人聊到的要点，全丢进收件箱，别管双链、别管分类、别管好不好看，先让写这个动作变成习惯。用一周它顶多是个能检索笔记的工具，用一个月才慢慢变成能参考的东西，用满半年，它才长成那台只属于你的知识引擎。

插件的正确顺序是同一种笔记反复出现，再做模板；同一个手工动作反复发生，再找插件。反过来先装一堆再找用途，就是纯给自己造活儿，而且一上来装十几二十个，启动变慢、界面变复杂、大部分根本没打开过。

一周之后再接 AI，你手上有真东西可读，它调的是你的笔记、你的研究、你的判断，给回来的是定制答案。空库直接接上去，它只能还你一个人人都拿得到的平均回答。

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 12. Obsidian 免费版够用吗，要不要买会员？说清边界

个人使用完全免费，核心编辑、双向链接、社区插件一样不少，没有按功能收费的墙。

付费的只有两样，一个是官方跨设备同步 Sync，一个是把库发成网页给别人看的 Publish。这两样都是额外服务，不是软件本身的功能锁。你在自己电脑上写、笔记全是本地 .md、用系统云盘或者坚果云同步，一分钱不用花，新手基本用不到这两个。

要不要买 Sync，算一笔账就清楚。标准版 4 美元一个月给一个库一 GB，Plus 版 8 美元一个月给十个库十 GB，8 美元一个月一年下来九十六美元，教育优惠打六折。这钱买的是省心，端到端加密、全平台原生、秒级实时、自带版本历史和冲突解决，出问题不用你自己查。不买就自己折腾，坚果云免费版给五 GB 空间、每月一 GB 上行流量，小库够用，库大了流量会吃紧。嫌它贵直接放弃是一种理由，在意数据存到了哪、流向如何自己看不见是另一种，两条都真实存在。

还有一点提前有数，iOS 是分水岭，不少免费方案在桌面端跑得欢，到 iPhone 上直接趴窝。手机版建议等你在电脑上把基本用法跑通了再装。

资源：Obsidian Sync https://obsidian.md/sync · Obsidian Publish https://obsidian.md/publish

## 13. 隐私敏感内容（日记/客户）一上来能不能交给云端 AI？

别急着交，先把该护住的护住，再谈让它多聪明。

先泼一盆冷水降降温，非定向地偷你笔记并不是常见威胁，攻击者更想要凭证、更想上勒索软件，那来钱快得多。真正该盯的是你自己主动打开的那些口子。社区插件对 vault 里的所有文件拥有完整且不受限的访问权限，任何一个插件技术上都能读走你全部笔记和附件，也能联网把它们发出去。官方给自己定的规矩是少即是安全，连画布这种明明有现成开源库的功能都从零自己撸，安装脚本一律不跑，你挑插件也该照搬这个姿态，只装你信得过的。

具体分两层来办。密码、API Key、身份证明这类根本不该进 vault，扔进密码管理器。日记、客户资料这类，要么走本地模型，数据一步不出这台机器；要么先加密再上云，比如用 Cryptomator 建一个保险箱，把库放进去，密钥只在你手里，云端那头就算被攻破，拿到的也是一堆解不开的乱码。这条路有个副作用，Obsidian 读不了没解锁的加密文件夹，第一次用容易以为数据丢了，记得先解锁保险箱再打开库。

真要让 AI 读你的库，权限只开到它完成任务需要的那几个文件夹，别把整个库连同不相干的私人资料一起递过去。

资源：Cryptomator https://cryptomator.org/

## 14. 最小可行路径：最小配置先体验一次"AI 读我的笔记"怎么做？

最轻的一条路根本不用装插件，去 Claude 网页端新建一个 Project，把几篇核心笔记传上去，之后所有对话自动关联这些文件。

零门槛，适合先试个水，缺点是文件得手动更新，不会自动同步。想直接在 Obsidian 里聊，就装 Copilot 插件，装完启用，右侧栏会多出一个聊天气泡。然后给它一个模型来源，配三样东西，Base URL 填服务商地址，结尾必须是 /v1；Model 填模型名，一字不差复制过去；API Key 只显示一次，立刻存进密码管理器，绝对不要进 git。配完在聊天面板打一句你好试试，几秒内有回复就算通了。

配不通就按这个顺序排查：Key 复制全了吗，前后有没有多余空格；Base URL 结尾那个 /v1 是多加了还是少加了斜杠；Model 名是不是一字不差；账户还有没有余额；用海外模型的话代理开了没有。

期待值也顺手调一调。问 AI 你自己写过的笔记里有什么，价值其实有限，相当于雇个人替你看你自己写的东西再转述一遍。真正值钱的用法是让它干你干不动的活，比如把你记过但早忘了的两篇笔记连起来，或者基于你这堆积累产出点新东西。

可复制模板（直接复制使用）：

```
Copilot 设置三项（以插件最新 README 为准）：
- Base URL：填到模型服务商地址，结尾必须是 /v1
- Model：填模型名，一字不差复制
- API Key：只显示一次，存进密码管理器，绝不进 git

排错清单：
1. API Key 复制完整了吗？前后有没有空格？
2. Base URL 结尾的 /v1 是不是多加或少加了 /？
3. Model Name 一字不差吗？
4. 账户还有余额吗？
5. 海外模型开代理了吗？
```

资源：Copilot https://community.obsidian.md/plugins/copilot
