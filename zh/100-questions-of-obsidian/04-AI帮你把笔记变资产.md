# 第四章 · AI 帮你把笔记变资产：从存到用

笔记攒了几百条还是一堆灰，问题不在记，在没用起来。接好 AI 之后真正的价值才开始：你攒的积累越能被 AI 基于它答出来，笔记才真正成了资产，不再是堆数字垃圾。这一章讲怎么让 AI 把积累变成能用的东西，从一份让 AI 读得懂你的身份文件，到一套 raw/wiki 分开的知识库结构，再到编译、问答、体检的日常循环。

## 47. 怎么让 AI 真正"读得懂我"，不用每次重新介绍一遍？

把一份 me.md 放在库根目录，写清你是谁、在做什么、在意什么、别对我做什么，AI 每次开新会话先读它。它相当于你的可移植身份，换任何一个 AI 来读都能用，你不用反复自我介绍。

具体做法就三块：身份（一句话职业/领域/现状）、在做的项目（主线副线加卡在哪）、对你的库怎么用（目录规则、双链宁少勿滥、回答要标来源）。Claude.md 里甚至可以只写一句"立刻去读 me.md"，AI 读到这句就去找那份身份文件。库的检索、回答、浮现都建立在它先懂你之上，否则它只能按字面猜。

可复制模板（直接复制使用）：

```
# me.md 最小骨架（放库根目录，让 AI 每次先读它）
---
type: profile
updated: 2026-08-10
---

## 我是谁
一句话：职业 / 领域 / 现在的身份

## 我在做什么
- 主线：[[项目A]]（目标是什么，现在卡在哪）
- 副线：[[项目B]]
- 长期在意的问题：

## 我的库怎么组织
- inbox/ 未加工 · notes/ 已加工 · wiki/ 概念页
- 命名规则：YYYY-MM-DD-主题
- 双链只连真有关系的，宁少勿滥

## 我要 AI 怎么做
- 回答基于本库，每条结论注明来源笔记
- 库里没有就直说，不要补
- 结论和措辞留给我，你只做归拢、检索、草稿
```

## 48. Vault QA 是什么，怎么让 AI 基于我的积累回答，不从零编？

Vault QA 就是把你的笔记当知识库，问之前 AI 先读库再答，答案来自你自己的积累。它成立的前提是笔记能被检索到，连得越密、加工越多，答得越准。

建两层就够：raw/ 放原始资料，wiki/ 放加工过的概念页，wiki/ 里留一份总目录 index.md。问之前先让 AI 读 index.md 摸清全貌，再要求它答完指出具体来源页，库里没有的如实说。这样你问"我去年关于 X 的结论是什么"，它翻的是你自己的笔记，不是网上的泛泛之谈。检索容易只捞到表面相关的几条，所以跨多年做综合判断时，你得把问题拆细，别指望一次问清。

可复制模板（直接复制使用）：

```
请先读取 wiki/index.md 了解全貌，然后根据 wiki/ 内容回答我的问题：[你的问题]
回答时引用 wiki/ 里的具体来源页面；知识库没有相关信息也请告诉我。

# 库的两层结构（照着建）
raw/    原始资料，保留 source_url，不加工
wiki/   加工过的概念页，每页顶部注明来源
wiki/index.md   总目录，AI 每次先读它
```

资源：Copilot for Obsidian https://community.obsidian.md/plugins/copilot

## 49. 怎么给 AI 写一份"库的使用说明书"，让它别乱来？

在库根放一个 CLAUDE.md（用 Codex 就写 AGENTS.md），把目录结构、页面格式、命名规则、摄入/查询/体检三种操作各自的步骤写清楚。这份文件是整个仓库里最重要的东西，没有它，AI 每次编译格式都不一样，页面该合并不合并，一个月后你得到一堆 AI 味碎片。

最小内容就三块：结构约定（raw/ 原始资料只进不改，wiki/ 是 AI 的地盘）、页面规则（每页带 frontmatter、内部引用用 [[wikilink]]、每个结论能追溯到 raw/ 来源）、铁律（NEVER 删除任何文件、NEVER 修改 raw/）。新页还是改页也有一条启发式：会被别的页面链接就新建，只是补充信息就原地更新。前几篇资料要一篇篇喂，把纠正写回 CLAUDE.md，训练好你的管理员再放量。

可复制模板（直接复制使用）：

```
# CLAUDE.md（放库根，AI 每次先读它）
## 结构
- raw/：原始资料，永远不要修改这里的任何文件
- wiki/：你生成和维护的 Markdown 页面
- wiki/index.md：总目录，每次操作后更新
- wiki/log.md：只追加的操作日志

## 页面规则
每个 wiki 页面必须带 frontmatter：
  title: 页面标题
  sources: [raw/下的来源文件路径]
  related: ["[[相关页面]]"]
- 内部引用一律用 [[wikilink]]
- 每个结论都要能追溯到 raw/ 里的来源，没有来源的结论不写

## Ingest 流程
1. 读 raw/ 里指定的新文件
2. 写摘要页，更新或新建相关概念页
3. 更新 index.md，追加 log.md

## Query 流程
1. 先读 index.md 找相关页面，读 2-3 个页面后作答
2. 答案里引用 [[页面]]，追溯原文时给 raw/ 路径

## Lint 流程
检查：页面间矛盾 / 被新资料推翻的旧结论 / 没有入链的孤儿页 /
被提到但没有页面的概念。输出报告，未经我同意不做任何删除。

## 铁律
- NEVER 删除任何文件
- NEVER 修改 raw/
- 新页 vs 改页：会被其他页面链接，就新建；只是补充信息，就原地更新
```

资源：Obsidian 属性（Properties）文档 https://help.obsidian.md/properties

## 50. 我的第二大脑会不会只是个日志本？怎么判断它真"会想"？

库大不等于会想。日志本是只记不处理，今天一条明天一条，彼此不连，回头看就是一堆流水。真会想，是记的时候你就下了判断：这两条有关联、那篇推翻了我之前的结论，并且你定期回头改。

三条自检最直接：笔记之间有没有连接、你回头加工过没有、写新东西时旧的能不能被用上。把收藏当努力、把库大当成长，囤的多半是自己从来不读的东西。三条都空，它就只是个日志本。你的库会不会想，直接决定将来 AI 基于它答出来的东西有没有根，光囤不回看，存下来的只是搬运，压根不算思考。

可复制模板（直接复制使用）：

```
# 你的第二大脑是「会想」还是「日志本」？三条自检
- 笔记之间有没有连接？（MOC / 双链）
- 你有没有回头加工过？（定期回顾、更新结论）
- 写新东西时旧的能不能被用上？（AI 基于积累答得出）
三条都空 → 只是搬运工，补上加工才算会想

# 量化第一条：把孤岛笔记全揪出来
# 需先安装并启用 Dataview 插件，再把下面三行放进语言标注为 dataview 的代码块
LIST
WHERE length(file.outlinks) = 0 AND length(file.inlinks) = 0
SORT file.mtime DESC
```

资源：Dataview https://community.obsidian.md/plugins/dataview

## 51. AI 知识库的三层结构长什么样，为什么要分 raw 和 wiki？

一套跑得通的 AI 知识库分三层：raw/ 放原始资料，wiki/ 放 AI 编译后的知识条目，库根再放一个 CLAUDE.md 写维护规则。raw/ 像仓库，只保管原始证据不加工；wiki/ 像书架，AI 把资料整理成能反复读、能链接、能更新的页面，带 index.md 总目录和 log.md 维护日志；CLAUDE.md 像说明书，告诉 AI raw/ 不能改、每条判断指向来源、每次整理完更新 index 和 log。

Obsidian 在这里不当 AI 本体，只当知识库 IDE，你用它看 raw、浏览 wiki、查链接关系。分开的好处是 AI 生成的 wiki 内容不会污染你的原始资料，追溯任何一条结论都能回到 raw/ 里的原文件。前 10 篇资料要一篇篇喂，边编译边把格式纠正写回 CLAUDE.md，训练好你的管理员再放量。

可复制模板（直接复制使用）：

```
AI 知识库/
├── raw/                 # 原始资料，只新增，不乱改
│   ├── articles/        # 外部文章、博客、教程
│   ├── papers/          # 论文、研究报告
│   └── clips/           # 网页剪藏、摘录
├── wiki/                # AI 编译后的知识条目
│   ├── index.md         # 知识库总目录，快速知道库里有什么
│   ├── log.md           # 维护日志，记录每次新增和编译
│   ├── concepts/        # 概念页，每个重要概念一个文件
│   ├── entities/        # 实体页：人、组织、产品、项目
│   ├── syntheses/       # 综合页，跨资料整合后的主题梳理
│   └── sources/         # 来源摘要页，每条原始资料一份
├── outputs/             # 问答、报告、健康检查
│   ├── qa/              # 复杂问题的答案存档
│   └── health/          # 健康检查报告
└── CLAUDE.md            # 写给 AI 的维护规则
```

资源：Various Complements https://community.obsidian.md/plugins/various-complements

## 52. 怎么让 AI 一次性把知识库架子搭好，我少动手？

给 AI 一段建库提示词，让它直接创建目录结构、总目录、维护日志和 CLAUDE.md，你拿到手就是能用的空架子。这一步叫 init，干完你再往里投喂资料。

提示词里要写清四件事：建哪些目录（raw 各类型子目录、wiki 的 concepts/entities/syntheses/sources、outputs 的 qa/health）、建 wiki/index.md 和 wiki/log.md、建 CLAUDE.md 写明维护规则（raw/ 只存不删不覆盖、每个判断指来源、不确定的标待核验）、在 sources/ 写一份来源摘要页模板（含 title/source/source_url/summary/key_points/related_concepts）。建完让 AI 用一段话告诉你这库怎么用。第一次别追求完美，先跑通，后面每轮再修。

可复制模板（直接复制使用）：

```
目标：
我想用 LLM Wiki 的思路搭一个普通人能用的 Markdown 知识库。这个库不做企业级 RAG，不上复杂数据库，先用文件夹和 Markdown 跑通最小闭环。

请你完成这些事：
1. 创建下面的目录结构：
   - raw/articles/
   - raw/papers/
   - raw/clips/
   - wiki/concepts/
   - wiki/entities/
   - wiki/syntheses/
   - wiki/sources/
   - outputs/qa/
   - outputs/health/
2. 创建 wiki/index.md，说明这个知识库当前有哪些主题、资料和入口。
3. 创建 wiki/log.md，记录每次新增资料、编译资料、更新页面和健康检查的结果。
4. 创建项目工程规则文件：用 Claude Code 就建 CLAUDE.md，不确定工具就同时建 AGENTS.md 和 CLAUDE.md（内容一致）。
   - raw/ 只保存原始资料，不要删除，不要覆盖。
   - 每个重要判断都尽量指向来源。
   - 不确定的信息标注待核验，不要编。
   - 每次整理完告诉我你改了哪些文件。
5. 在 wiki/sources/README.md 写来源摘要页模板：title / source / source_url / created / summary / key_points / related_concepts。
6. 在 outputs/health/README.md 写健康检查说明：缺来源的页、冲突的概念、无链接的页、可能过期的判断。

请直接创建这些目录和文件。完成后，用一段话告诉我这个知识库现在怎么用。
```

## 53. 新资料进来，怎么让 AI 自动把它编译进知识库？

每丢一篇新资料进 raw/，给 AI 一段编译提示词，让它生成来源摘要页、更新概念页、刷新总目录和日志，你手上就有份带出处的骨架。这个动作叫 compile，是 wiki 持续复利的关键。

提示词要它做五件事：为每篇资料生成来源摘要页并保留 source_url；提取重要概念，已有的概念页就更新、没有就新建；更新 wiki/index.md 让你快速知道库里有什么；更新 wiki/log.md 记录这次处理了哪些资料；不删除 raw/ 里的原始资料。第一次编译别追求完美，AI 可能漏重点、归类可能不对，先跑通。编译完回 Obsidian 翻十分钟：来源摘要保留原文链接没、概念页逻辑通不通、index 列全了没，问题记下来下一轮让它修。

可复制模板（直接复制使用）：

```
请读取 raw/ 里的新增资料，把它们编译进 wiki/。

你要做这些事：
1. 为每篇资料生成一份来源摘要页，保留 source_url。
2. 提取重要概念，如果 wiki/concepts/ 里已有相关页面，就更新旧页面；没有就新建。
3. 更新 wiki/index.md，让我能快速知道现在库里有什么。
4. 更新 wiki/log.md，记录这次处理了哪些资料。
5. 不要删除 raw/ 里的原始资料。
```

## 54. 怎么让 AI 基于 wiki 回答，并且每条结论都标出来源？

提问前先让它读 wiki/index.md 摸清全貌，再基于 wiki/ 内容作答，并要求它引用具体来源页面，库里没有就直说。这样答案来自你自己的积累，不是网上的泛泛之谈。

提示词就两句核心：先读 index.md 了解全貌，再根据 wiki/ 回答你的问题，引用 wiki/ 里的具体来源页面，没有相关信息也告诉你。复杂问题的答案让它存到 outputs/qa/。光靠问答还不够，得定期跑健康检查：读 index.md，找出缺来源的页、互相冲突的概念、像孤岛没链接的页、被反复提到却还没独立成页的概念，报告存到 outputs/health/ 并给出最优先修的 5 个问题。检查也能用 Dataview 写成常驻查询，社区有现成示例库能直接抄。

可复制模板（直接复制使用）：

```
# 提问（先问库，不从头搜互联网）
请先读取 wiki/index.md 了解当前知识库的全貌，然后根据 wiki/ 里的内容回答我的问题：[你的问题]
回答时请引用 wiki/ 里的具体来源页面。如果知识库里没有相关信息，也请告诉我。

# 健康检查（每周跑一次）
请先读取 wiki/index.md 了解当前知识库的全貌，然后做一次健康检查。
重点检查：
1. 哪些页面缺少来源。
2. 哪些概念定义互相冲突。
3. 哪些页面几乎没有链接，像孤岛。
4. 哪些重要概念被多次提到，但还没有独立页面。
5. 哪些页面可能已经过期，需要重新核验。
请把报告保存到 outputs/health/，并给出最优先修复的 5 个问题。
```

## 55. AI 给的回答我要不要全信？怎么当场识破它编的？

AI 基于你的库回答，不代表它不会错。RAG 检索只取 top 3-5，相关笔记没进前几名它就只能瞎编，而且它是语义检索不是关键词检索，像"1 on 1"这种短词还会被预处理当停用词丢掉，根本没检索到。

三个办法当场识破。第一，看它答的时候有没有指向具体某篇笔记，泛泛而谈、没出处的先打个问号。第二，追问"你刚才引用的是我哪篇笔记里的哪句话"，真读了库的指得出来，编的当场露馅。第三，拿你明明知道的事实去对，你记得写过相反结论它却说库里没有，那就是幻觉。最后一关始终是你自己已知的判断，别把 ChatGPT 当不会错的 oracle，它本来就是预测文本生成器。

可复制模板（直接复制使用）：

```
# 识别 AI 幻觉：三句追问（复制去问）
1. 你刚才引用的是我哪篇笔记里的哪句话？
2. 把那句话原样贴出来给我看
3. 我用已知事实对：我记过相反结论，你说没有，请解释
答不出具体出处 → 大概率在编，别采纳
```

资源：Smart Connections https://github.com/brianpetro/obsidian-smart-connections

## 56. 怎么让 AI 给库做"定期体检"，别越整理越乱？

放手让 AI 整理，最常见的结果是库没变清楚，反倒多出一层没来源的 AI 生成页，垃圾堆上又叠一层。挡住它的办法是定期 Lint，把每一轮产出都过一遍。

Lint 流程就查四样：页面之间有没有矛盾、有没有被新资料推翻的旧结论、有没有没入链的孤儿页、有没有被提到却没有独立页面的概念。报告只当清单看，删还是补由你定，而且未经你同意 AI 不能做任何删除。这类检查也能写成常驻查询，社区有现成示例库可以直接抄，比自己从零写准得多。AI 整理是一轮一轮地审，每轮把来源和连接理清，库才不会越整越脏。

可复制模板（直接复制使用）：

```
# 定期 Lint：逼它真的读了库（复制去问 AI）
审查整个 wiki/：找出互相矛盾的页面、被新资料推翻的结论、
无来源的孤儿页，给报告并建议值得新建的空白概念。
未经我同意不做任何删除。

# 常驻查询：揪出缺来源的页
# 需先安装并启用 Dataview 插件，再把下面三行放进语言标注为 dataview 的代码块
TABLE file.mtime AS 修改时间
FROM "wiki"
WHERE !source AND !source_url
```

资源：Dataview https://community.obsidian.md/plugins/dataview · Dataview 示例库 https://github.com/s-blu/obsidian_dataview_example_vault

## 57. 把 AI 当第二大脑，认知萎缩的风险怎么防？

认知萎缩发生在用得好的人身上，因为 AI 太方便，你容易把思考那块也交出去。三个风险摆在那儿：记忆萎缩，什么都存库里自己不记；吸收萎缩，只读 AI 给的摘要不读原文；能力错觉，以为库里有就等于自己懂了。

守住三道防线就行：关键判断自己下，AI 给的摘要至少偶尔回去看一眼原文，每篇笔记保留一段自己写的话。判断一篇笔记有没有过关，看它里面有没有一句只有你写得出来的话。生成性加工的理论说，学习发生在外部任务引发内部认知加工之时，连笔记到已有知识就是典型的生成性活动，光存不加工压根不触发它。第二大脑是外挂，思考那块始终是你自己的。

可复制模板（直接复制使用）：

```
# 认知萎缩三风险 + 三道防线
风险：① 记忆萎缩（只存不记）② 吸收萎缩（只读摘要不读原文）③ 能力错觉（以为有=懂）
防线：① 关键判断自己下 ② AI 摘要至少偶尔回看原文 ③ 每篇保留自己写的那一段
第二大脑是外挂；思考那块始终是你自己的。

## 今天我自己想明白的一件事
（不许粘贴，不许让 AI 代写，一句话也算）

## 59. 双链被 AI 用上是什么体验，为什么认真连链值得？

AI 读你的库不只是关键词匹配，它会沿双链做图检索：你连过的两篇，它默认相关，一并捞出来。连对的链，直接换成检索质量。

你问一个概念，它不只找标题命中的那篇，还把通过双链连着的几篇一起调出来，哪怕那几篇里从没出现过你问的词。判断一条链该不该连，只问一句：将来我看到 A 的时候，会想找 B 吗。随手乱连会制造噪音，连得少而准，AI 明显更懂你。每条永久笔记至少带两条显式链接，第一条通常明显，第二条才需要你想清楚它怎么嵌进已有网络，正是这下费劲的思考产出更好的连接。

可复制模板（直接复制使用）：

```
# 连链的取舍（每写完一篇过一遍）
问自己：将来我看到 A 时，会想找 B 吗？
  会 → 连；犹豫 → 不连（宁缺勿滥）
每篇至少留 1 条出链，指向一篇更上位的 MOC 或概念页

# 每周 10 分钟补链（复制去问 AI）
请列出我库里出链和入链都为 0 的笔记，按修改时间排序；
每篇给我 2 条候选双链和一句理由，我来定连不连。
```

## 60. AI 帮我做周期性回顾和周报，怎么不让它替我想、只替我写？

AI 干回顾的边界要划死：它替你写，不替你想。把日记、项目笔记、会议记录都给它，让它出初稿；哪些事重要、怎么措辞、哪些该展开，你来定。

具体做法是固定一个你真会执行的最低频率，比如每两周翻一次收件箱和本周新增，回顾集中放在周末，靠打开笔记这个动作触发，比靠提醒可靠。周报模板里留白最关键："本周最大收获""下周重点"两栏必须空着交上来，逼你自己填。它省的是打字和归纳的力气，判断那一块留给你，周报里真正值钱的就是这两栏，AI 给不了。标准元数据（统一标签、日期、项目关联）也能降低 AI 检索成本。

可复制模板（直接复制使用）：

```
# 让 AI 出周报草稿（你定结论）
请基于我本周的日记、项目笔记、会议记录，起草一份周报初稿：
1. 列本周推进的事（按项目分组）
2. 标出值得展开的重点
3. "本周最大收获""下周重点"两栏留空，我自己填
只替我写、不替我想，结论和措辞由我定。

## 61. 笔记之间的隐性关系，AI 能挖出来吗？怎么挖？

能挖，这是 AI 比人强的地方。隐性关系藏在语义里，你记的时候没意识到这两篇有关，AI 读完全库能比对出来，比如半年前记的一个项目的坑，和上个月另一个项目的类似问题。

挖得准不准，全看指令限得死不死：给定时间范围、要求输出成对的笔记名、每对附一句关系判断。不限范围，它只会给你一堆"都跟效率有关"这种空话。挖出来的对子你自己审，认了就补一条双链，下次检索立刻用得上。前提照旧，笔记得有实质内容，空库挖不出东西。每周让 AI 扫一遍最近新建和修改的笔记，找还没显式连上的强关联，这种活人懒得干，AI 干得动。

可复制模板（直接复制使用）：

```
# 隐性关系挖掘（限时间范围 + 成对输出 + 关系判断）
请只看我 2025-01-01 到 2026-08-01 之间创建的笔记。
找出 10 对「内容明显相关、但目前没有双链连接」的笔记，按下面格式输出：

[[笔记A]] ←→ [[笔记B]]
关系：一句话说清为什么相关，从这几类里选一个：
      同一个坑 / 互相印证 / 后者推翻前者 / 同一方法的两次应用 / 同一问题的不同阶段

要求：
1. 只输出库里真实存在的笔记名，不要编造
2. 关系写具体，"都与效率有关"这类空话不要
3. 拿不准的对子单独放进"存疑"一栏
4. 最后告诉我：这 10 对里，哪一对最值得我今天就去补链
```

## 62. 我的 vault 跨了几年，AI 怎么用 Dataview 自动索引"时间里的我"？

## 63. 怎么用 daily notes 把散落的笔记串成"时间里的我"？

## 64. 标签和属性体系怎么设计，才让 AI 检索不跑偏？

AI 检索靠的是 frontmatter 里的结构化字段，你脑子里那套分类它读不动。把 type、status、created、tags 这几项固定下来，Dataview 查询和 AI 过滤才有抓手，否则它只能靠全文猜。

命名约定做成"类型+状态+日期+主题"，搜部分关键词就能定位任何笔记：你知道类型、大致什么时候建的、主题是什么，三样信息让每篇不用翻文件夹就找得到。标签用扁平的具体词（productivity、compounding、knowledge-systems 这种），别叠深层层级，AI 按标签聚类和按属性过滤都更准。标准化元数据（统一标签、日期、项目关联格式）能直接降低 AI 检索成本。每条永久笔记的 frontmatter 都把类型标清楚，模型九成场合能判对该新建页还是改旧页。
