# 第六章 · 插件生态与进阶玩法：开眼界，不迷路

插件装多了 vault 会拖慢、更容易劝退。这一章不讲怎么把插件装满，讲装哪些、不装哪些，以及几个能开眼界的玩法。进阶的东西知道有这条路就行，别一上来就冲。插件再花哨，也是为你自己的积累服务的，根还是你那座 vault。

## 83. Obsidian 到底有没有官方 AI？没有的话社区插件怎么挑？

Obsidian 没有内置 AI，AI 能力全部来自社区插件，等官方出功能是等不到的，所以挑插件的本事得自己练。官方在 2026 年 5 月上线了 Obsidian Community 新目录，给每个插件打了安全记分卡，你挑插件第一次有了官方的安全分级可参考，而不是只靠下载量猜。

挑一个插件值不值得装，用三条硬指标，凑不齐三个"是"就先放回去。第一看更新频率：打开它的 GitHub 仓库，最近一次提交在半年内，说明作者还在维护。第二看 issue 响应：按最新排序翻最近十条 issue，作者回过一半以上，出问题才找得到人问。第三看功能边界：README 首屏能用一句话说清它做什么；一个插件塞了七八个不相干的能力，性能负担和维护风险会一起来。插件如果过不了新的自动审查，最终会从目录里消失，这也是个新的考量维度。更要紧的是，社区插件能读你 vault 里的任何文件，来源多一层风险就多一层。

装的路径是设置 → 第三方插件 → 关闭安全模式 → 浏览 → 搜名字 → 安装，回到列表把开关打开。最后这步最容易漏，装完不启用等于没装。

```
# 装插件前的三问（答案写进笔记，少一个「是」就不装）
1 更新频率：GitHub → Commits，最近一次提交是否在 6 个月内？
2 issue 响应：Issues 按最新排序，最近 10 条里作者回了几条？少于 5 条记「否」
3 功能边界：README 首屏能否一句话说清它做什么？超过 3 个不相干功能记「否」
补充：市场里看下载量，低于 1 万的小众插件，只在前三问全「是」时才装
装完记一行：我装它是为了解决 ______ 这个卡点；填不出来就卸载
```

资源：Obsidian Stats https://www.obsidianstats.com · 官方插件目录 https://obsidian.md/plugins

## 84. 装哪些、不装哪些：2026 年最值得留下的 2–3 个插件

常驻插件控制在三个以内，每多装一个，你都要说得出它替你省掉了哪一步操作。一个程序员为了安全把 Homepage、Nldates 重写成几十行、把 Obsidian Git 换成 cronjob，逻辑就一条：插件能读你 vault 里的全部笔记，能不装的就不装，这跟官方"少即是安全"的姿态是一个道理。插件再多也解决不了"今天该写什么、该删什么"这种决策，工具是给你省步骤的，不是替你思考的。

个人 vault 加 AI 这条线，值得长期留下的只有三类能力：在库里直接问答、写作时自动浮现旧笔记、模型跑在本地。对应到具体插件：Copilot 负责基于笔记问答和处理选中文字；Smart Connections 负责你写着写着在侧栏推出相关旧笔记；Ollama 负责把模型拉到本地，在 Copilot 里把地址指向它，对话就不再走云端。三个装完先用两周，两周内没主动打开过的那个直接停用。

不建议留的是只改观感的那一类：花哨主题、动画、装饰型看板。它们每次启动都要参与加载，收益却只在第一天。

```
# 1 装好 Ollama 后拉一个中文够用的小模型
ollama pull qwen2.5:7b
# 2 允许 Obsidian 访问本地服务，改完重启 Ollama
launchctl setenv OLLAMA_ORIGINS "app://obsidian.md*"    # macOS
setx OLLAMA_ORIGINS "app://obsidian.md*"                # Windows
# 3 Copilot 设置 → Model → Add Custom Model
#   Provider: ollama   Base URL: http://localhost:11434   Model: qwen2.5:7b
# 4 验证：断开网络再问一句，能答说明走的是本地模型
```

## 85. 模板和开箱 vault 去哪找？除了自己造，有没有能直接抄的？

别从空白页造系统，也别迷信别人的成品库。论坛里一个用了五年的老用户给过提醒：从一个空 vault 起步、别套用别人的 starter kit 是更好的，因为别人的结构是按他的脑子长的，你搬进来只会一直读他的库、写不进自己的东西。一个现成的反例是 Ideaverse Zero，默认就开着三十个社区插件，老笔记本上打字要等上几秒才出字，卡顿的元凶就是那堆预装插件。第三方目录只用来做调研，看下载量和更新活跃度，真正下载走官方市场或作者仓库，插件能读你全库文件，来源多一层风险就多一层。

真想抄，挑一个最贴近你当下用途的骨架，下载后当天就把示例内容换成你自己的三篇真笔记；换不进去，说明这套结构不适合你，删掉换下一个。想要中文语境下的 MOC 打法，LYT Kit 有中文版仓库，clone 下来就能改。拿到之后第一件事是清场：把模板目录之外的示例笔记全部挪走，只留文件夹骨架和模板文件。留着别人的示例内容，你会一直在读别人的库。

```
# 拿一份中文 MOC 骨架，改成自己的库
git clone https://github.com/nickmilo/LYT-Kit-in-Mandarin.git my-vault
cd my-vault && rm -rf .git
# 先列出示例笔记看清楚，确认无误再执行下一行
find . -name "*.md" -not -path "./Templates/*"
# 示例内容先挪进待删目录，留一天再删
mkdir -p _to-delete
find . -name "*.md" -not -path "./Templates/*" -not -path "./_to-delete/*" -exec mv {} _to-delete/ \;
# Obsidian：打开文件夹作为仓库 → 选 my-vault → 从三篇真笔记开始
```

## 86. 双链=GraphRAG 是炒作还是真有用，普通用户怎么受益？

真有用，成立条件是链连得少而准。图检索的收益来自链接携带的关系信息，一旦你靠自动补全把所有同名词都连上，图上每个节点都通向一切，检索时等于没有信息。

普通用户受益的场景很具体：你问一个概念，AI 除了返回标题命中的笔记，还会把与它有链接关系的几篇一并带出来，哪怕那几篇里根本没出现你问的词。这种召回，关键词搜索做不到。

今天能落地的动作是量一下自己库的链接质量。一个开发者在 vault 到了四百条笔记时撞上"库烂掉"。他的判断是库烂不是单条笔记写得差，是图谱结构出了问题。先查出链超过 20 条的笔记，这些多半是被自动补全污染的中转站，手动砍到 5 条以内，只留你说得清关系的那几条；再查一条出链都没有的长笔记，给每篇补一条真实的上位链接。这两件事做完，AI 沿图检索的结果会明显变准。

```dataview
TABLE length(file.outlinks) AS 出链数, file.folder AS 目录
FROM ""
WHERE length(file.outlinks) > 20
SORT length(file.outlinks) DESC
```

```dataview
LIST
FROM ""
WHERE length(file.outlinks) = 0 AND file.size > 500
SORT file.mtime DESC
LIMIT 30
```

## 87. Agentic+MCP 是什么，为什么说它是"给想更进一步的人"？

这条路先别急着上。判断标准只有一条：你库里是否已经存在每周重复三次以上、步骤固定的操作，比如把散在日记里的待办汇总成一页、给新笔记批量补 frontmatter。有这种活，交给智能体才划算；没有，装完只是看它空转。

先把两个词分清。Agentic 指模型自己决定分几步、调用哪个工具完成一件事，不用你一句句喂指令。MCP 是一套标准接口，让模型能读写你本地的文件和应用；Obsidian 这边通过 Local REST API 插件在本机开一个端口，供客户端连接。一个有公信力的长期写作者真把 filesystem MCP 接到自己的 vault 上跑过，结论是它比她试过的绝大多数 AI 工具都异常可靠，因为给模型的接口受限、明确、可验证，幻觉的空间被压扁了。

落地顺序是三步：先按可见性把目录分三档，再写一份规则文件放在库根，最后只给只读权限跑一周。一周里检查它有没有越界读 private，没有再放开写权限。

```
# 放在库根，命名 CLAUDE.md 或 AGENTS.md，智能体每次对话先读它
## 目录权限（三档，越界即停）
- 00-private/   禁止读取。日记、体检、合同、账号线索都在这里
- 10-inbox/     只读。可以引用，不可改写
- 20-notes/     可读可写。新建笔记只允许放这里
## 写入规则
1 任何写操作先输出 diff 给我确认，我回复「同意」才执行
2 不允许删除文件，只允许移动到 99-trash/
3 新建笔记必须带 frontmatter：title / created / tags
4 修改已有笔记时保留原有双链，不许把 [[链接]] 改成纯文本
5 每轮结束列出你读过和改过的文件清单
```

## 88. 让 Claude/ChatGPT 也能读我的 vault，最小可行接法？

接法分两档，按使用频率选。一周问几次、每次只涉及几篇笔记，把那几个文件夹直接拖进对话窗口就够了，零配置零成本。要它跨会话反复读写整座库，才值得配 MCP，因为真把 agent 接进来是为了让它动手干那些读很多文件、按规则改写的体力活，不是偶尔问一句话。

不管走哪档，先在库根放一份说明书。外部模型没有你的上下文，它不知道 inbox 是碎片、notes 里才是成稿，说明书省下的就是这些反复解释的话。写清目录含义、命名规则、双链写法、哪些目录不许碰，写一次长期复用，换模型也不用重写。一个有公信力的长期写作者真把 filesystem MCP 接到自己 vault 上跑过，结论就是它比多数 AI 工具都异常可靠，因为模型拿到的是受限、明确、可验证的接口。

第二档的最小配置：Obsidian 装 Local REST API 插件，复制里面的 API key，填进客户端的 MCP 配置，重启。配完先问一句"列出我库里的顶层目录"，列对了再往下用。

```
# 库根 README-for-AI.md，外部模型每次对话第一件事读它
本库是本地 Markdown 文件，目录含义如下：
- 00-private/  禁止读取，任何情况下都不要引用其中内容
- 10-inbox/    未整理的碎片，可引用，不要当结论
- 20-notes/    成稿笔记，回答优先用这里的内容
- 30-refs/     摘录和原文，引用时必须写明来源文件名
规则：
1 回答必须标注来源，格式 [[文件名]]
2 库里没写到的内容直接说「库中未覆盖」，不要用通用知识补齐
3 需要新建笔记时，输出完整 Markdown 给我，由我自己落盘
```

## 89. 资讯、教程、社区去哪追？怎么不被教程海淹死？

订阅一堆源、每天刷到新玩法就照做一遍，最后库里全是半成品配置。教程海淹人的原因是它更新得比你实践快，你永远在追新，库里一个字没加。收藏了一堆 setup 看起来像在产出，其实只是模仿了生产力，这条叫"信息收藏癖谬误"，所以追资讯要先认这个账：收集本身不产生东西。

值得留的就三类：一份社区周报，把新插件和踩坑汇总好，一周扫十分钟；一个问答现场，在论坛里搜具体报错，比看教程快得多；一份索引清单，按类收好插件、主题、模板，查东西先翻它。订阅源控制在五个以内，优先选每周汇总型，跳过日更型。

护栏是一条动作规则：刷到的任何玩法先存进收件箱，写清它解决你哪个具体问题，一周后回看，还说得出问题的才动手。大多数条目活不过这一周，这正说明它们本来就不该占你的时间。

```
# 10-inbox/ 里新建一条，文件名：灵感-YYYYMMDD-关键词
---
type: idea
source: 原文链接
created: 2026-08-10
review: 2026-08-17
---
它解决我哪个具体问题：
（写不出来就直接删掉这条，不要存）
我要动的第一步：
（一句话，20 分钟内能做完）
一周后复看结论：采用 / 放弃
```

## 90. 插件和主题除了官方市场，还能去哪淘？国内怎么顺畅装？怎么挑不被坑？

第三方目录只用来做调研，看下载量、更新活跃度、有没有还没进官方市场的 beta；真正下载这一步，回到官方市场或作者仓库的 Releases 页。插件是能读你全库文件的代码，来源多一层，风险就多一层。国内装不上时按顺序处理：先判断是不是网络问题，浏览器能打开 GitHub 而客户端市场打不开，说明客户端通道被卡；接着走手动安装，从作者 Releases 下载三个文件扔进插件目录，这条路不依赖任何加速服务；确实需要加速服务时，选能对得上官方版本号的。

挑插件的红线三条：半年无更新、要网络权限却说不清传什么、作者仓库已归档。命中任意一条就跳过。白板类思维导图插件尤其要小心，有用户反馈某插件重开时原文件内容被全部清空，这种"动态布局"需求和静态白板的定位本来就冲突，大规模思维导图还是交给专业工具更稳。

```
# 手动装插件（客户端连不上市场时用，以 dataview 为例）
# 1 到作者 Releases 页下载三个文件：main.js  manifest.json  styles.css
# 2 目录名必须用 manifest.json 里的 id，不要自己起名
mkdir -p "<你的库>/.obsidian/plugins/dataview"
mv ~/Downloads/main.js ~/Downloads/manifest.json ~/Downloads/styles.css \
   "<你的库>/.obsidian/plugins/dataview/"
# 3 Obsidian：设置 → 第三方插件 → 重新加载插件 → 打开开关
# 4 核对版本：manifest.json 里的 version 与 Releases 页 tag 一致，不一致就重来
```

## 91. 我的 vault 越用越卡，怎么体检和瘦身？

卡不是因为笔记多，CEO 自己四万个 md 文件也跑得动。一个开发者在 vault 到四百条笔记时撞上"库烂掉"，他的判断很准：库烂不是单条笔记写得差，是图谱结构出了问题。慢的来源主要有两类：常驻插件数和附件体积。按这个顺序排查，多数库就不卡了。

第一步数插件：设置里看已启用数量，分批停用，每停一批重启一次，记下启动耗时的变化。Obsidian 自带一个几乎没人知道的秒表工具，路径是设置 → 通用 → 高级 → 点秒表图标，它会列出每个插件的启动耗时，可复制到剪贴板。有用户靠它查出 Templater 把启动从十秒拖到一两分钟，换掉后立刻回到十秒以内。第二步查附件：在库根跑命令找出超过 5 MB 的文件，大 PDF 和录屏挪到库外，用绝对路径引用。第三步才是内容体检，用下面三条 Dataview 查询各扫一遍。

判定标准给你：零反链的孤儿笔记可能内容很好，但功能上是隐形的，这种越多库越"烂"；缺 frontmatter 的笔记在查询里是隐形的，应该尽量清零。查完当天就处理掉，别攒到下一轮。

```dataview
TABLE length(file.inlinks) AS 入链, length(file.outlinks) AS 出链, file.mtime AS 最后修改
FROM ""
WHERE length(file.inlinks) = 0 AND length(file.outlinks) = 0
SORT file.mtime ASC
```

```dataview
TABLE file.folder AS 目录, file.mtime AS 最后修改
FROM ""
WHERE length(values(file.frontmatter)) = 0
SORT file.mtime DESC
LIMIT 50
```

```dataview
TABLE file.size AS 字节数, file.folder AS 目录
FROM ""
WHERE file.size < 200
SORT file.size ASC
```

```
# 附件体检（在库根执行）
find . -type f -size +5M -not -path "./.obsidian/*" -exec du -h {} + | sort -rh | head -20
find . -name "*.md" -not -path "./.obsidian/*" | wc -l    # 笔记总数
du -sh .                                                   # 库总体积
```

## 92. 想从 Obsidian 迁走，本地 Markdown 真能说走就走吗？

能说走就走，前提是你的正文没被插件语法绑架。一个自测方法很直接：关掉全部第三方插件重启，随机翻十篇笔记，满屏渲染不出来的代码块和字段，那部分内容就已经绑在插件上了。

迁之前先统计。dataview 代码块、tasks 标记、excalidraw 文件，这三类在别的编辑器里都会退化成原始文本。数量少就手动改成静态内容；数量多，先把它们集中到一个目录，迁走时单独处理，别混在正文里。四万个文件的库，迁走时就是直接把文件夹拷到新机器，本地 Markdown 的可携性经得起这个量级。真迁的时候只有两件事：整个文件夹拷走，附件目录一起拷；双链语法在支持 wiki 链接的编辑器里可以直接用，不支持的用一条命令批量转成标准 Markdown 链接，转换必须在备份上先跑一遍。

````
# 1 迁移前体检（在库根执行）
grep -rl '```dataview' --include=*.md . | wc -l      # 依赖 Dataview 才能渲染的笔记数
grep -rl '```tasks'    --include=*.md . | wc -l
find . -name "*.excalidraw.md" | wc -l
