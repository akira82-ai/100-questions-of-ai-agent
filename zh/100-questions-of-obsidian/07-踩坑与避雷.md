# 第七章 · 踩坑与避雷

前面六章都在教你怎么把对话落进自己的 vault，让 AI 真正为你工作。这一章把镜头反过来，专讲翻车现场。这些坑几乎人人都踩，区别只是早掉还是晚掉。把下面八条当成反面教材，比等自己撞上去便宜得多。

## 93. 新手最容易踩哪 5 个坑？

新手翻车基本都栽在同一批动作上，先把三条硬线立住：常驻插件别超过两个、文件夹别超过两级、第一周只写笔记不搭系统。

这五个坑翻来覆去就那几样：第一周装十几个插件、文件夹套四五层、每篇硬连十几条链、照搬别人的完美结构、攒几千条从不回看。自查信号很好认，这一周你改了五次文件夹结构却一条新笔记没写，打开库要等好几秒，图谱上一个节点挂着十几条线你却说不出哪条有用，库里几千条笔记这一个月一条都没回头翻过。中任意两条，就先别往里加东西，把下面三个数字量出来再说。

补救的顺序是先减后加。插件超线，按"这周用过没有"停用，先不删，两周内没想起它再卸载。文件夹太深不用一层层挪，在第二层建一条 MOC 笔记，把深处的内容用链接挂上来，物理结构保持扁平。双链宁少勿多，每连一条都要说得出为什么连。别人的库是别人的，照搬过来第一天你就陷在整理里出不来。

```bash
# 在 vault 根目录跑，哪个数字超线就先处理哪个
ls .obsidian/plugins | wc -l
# 已装插件数，超过 2 个先停用一批

find . -type d -not -path "./.obsidian*" | awk -F/ '{print NF-1}' | sort -rn | head -1
# 最大目录层级，超过 2 就用 MOC 压平

find . -name "*.md" -mtime -7 | wc -l
# 近 7 天动过的笔记数，等于 0 说明你在整理、没在写
```

```
# 新手 5 坑对照（中了就照右边改）
1 装一堆插件            → 只留 2 个，跑顺再添
2 文件夹套四五层        → 不超两级，深了用 MOC 挂链接
3 每篇硬连十几条链      → 连得少而准，说不出理由就不连
4 搬来别人的完美结构    → 先写一两条真笔记，结构后长出来
5 攒几千条从不回看      → 每月回顾一次，别养死档案
```

## 94. 把 AI 当“替你想”的人，最后都怎么样了？

把 AI 当成替你想的人，退化的是自己的判断力，而且这个过程没有痛感，用得越顺退化越快，等你发现时半年已经过去了。立场很简单：AI 负责把可能性摆开，判断这一步始终归你。

三个信号说明你已经踩进去了。翻最近十条笔记，AI 原文占了一半以上，你自己的判断句一句都数不出来。昨天让它总结的那篇长文，今天你复述不出结论，只记得"它说挺好的"。面对空白页的第一反应是打开对话框，而你以前会先写三行乱七八糟的想法。

补救靠反着用它。别让它出结论，让它出问题。先自己写满 200 字，再把这 200 字丢给它挑刺，它列出来的漏洞你逐条判断，接受哪条、驳回哪条都补一句理由，这句理由才是你的东西。库里放 AI 生成的内容前先砍掉一半，砍的过程逼着你判断哪句真有用，留下的那一半你一定读过。AI 帮你做整理、归类这些体力活很值，但替你想这件事它做不来，效果并不比一次普通对话强，别把判断权悄悄交出去。

```
# 反向提示词：让 AI 逼我想，别替我想
你现在是我的提问者，不许给结论，不许给建议。

我对「<主题>」的初稿想法如下：
<粘贴你自己写的 200 字，不许让 AI 代笔>

只做三件事：
1 逐条指出我这段里没有证据支撑的判断
2 提三个我没考虑到的反面情形，每条一句话
3 用一句话复述我的核心主张，让我确认你有没有理解偏

最后问我一个问题，问完停下，等我回答。
```

依赖：任意对话模型，库内使用可配合 Copilot 插件

## 95. 接了 AI 反而笔记更乱，怎么避免变成“AI 垃圾场”？

接了 AI 笔记反而更乱，根子在 AI 产物和你写的东西混在同一个池子里，而且没有出库口。池子脏了以后，你搜自己的东西反而搜不到自己的字。

自查很快。搜一个你熟悉的关键词，前五条结果里有三条以上是你没读过的 AI 文本，说明池子已经脏了。再挑一条笔记问自己"这段是我写的还是它写的"，答不上来问题更大，你的库已经开始骗你。规矩就两条：所有 AI 产物先落进 `10-AI草稿/`，一周内你没改写过的，一律删。

动作分两层。第一层给每份 AI 产物加 source 和 reviewed 两个属性，字段固定住才查得出来。第二层每周五跑一次查询，列表里的东西只有两个下场，你改写过、把 reviewed 置为 true、移出草稿区，或者直接删掉。改写的标准是删一半，再补一句你自己的判断。双链只连你读过的内容，AI 自动生成的链接看着热闹，点进去全是你没见过的句子，图谱越来越好看也越来越没用。

```yaml
---
source: ai          # ai 或 me，AI 产物一律标 ai
reviewed: false     # 你改写过才置为 true
created: 2026-08-10
---
```

```
TABLE created AS 生成日期, file.folder AS 位置
FROM "10-AI草稿"
WHERE source = "ai" AND reviewed != true
  AND date(today) - created > dur(7 days)
SORT created ASC
```

依赖：Dataview 插件，代码块类型写 dataview

资源：Dataview https://community.obsidian.md/plugins/dataview · File Cleaner https://community.obsidian.md/plugins/obsidian-file-cleaner

## 96. 隐私三件套是哪三样：私有数据、不可信内容、外传通道？

本地文件不等于安全文件。Obsidian 常年开着，库大部分时间处于明文状态，同一台机器上别的程序读得到。先想清楚你怕的是谁，再决定挡哪一层，一上来全盘加密只会让你自己用着别扭。

三件事分开挡。私有数据靠加密，敏感目录单独裹一层再同步；不可信内容靠人工过目，AI 给的东西会编，进库前你看一眼；外传通道靠事前判断，发给云端模型之前先想清楚这段值不值得出本地。给智能体的权限也分三档，private 完全不可读、readonly 只读不许改、work 才允许它建和改，只让它碰你想让它碰的那部分。Key 不要写进会被同步的 md 配置，用环境变量或系统钥匙串兜着，这样即便库泄露，别人也只拿到一段读不懂的占位。

已经出事的信号有两个，一条命令就能扫出来：库里存在明文写的密钥或密码，插件配置文件 `data.json` 里躺着你的 API Key。命中就立刻把内容挪出库，并且到服务商后台轮换那把 Key。只删笔记没用，Key 早就进过同步历史。

```bash
# 在 vault 根目录扫明文密钥，命中即处理
grep -rnE "sk-[A-Za-z0-9]{20,}|api[_-]?key[[:space:]]*[:=]|password[[:space:]]*[:=]" . --include="*.md"

# 顺手确认插件配置里没有明文 Key
grep -rn "apiKey" .obsidian/plugins/*/data.json

# 命中后的三步：挪出库 → 后台轮换 Key → 把密钥交给系统钥匙串或环境变量
```

```
# 智能体三档文件夹权限（写进库根目录，让它照此执行）
private/    日记、体检、合同、客户名单      完全不可读
readonly/   读书摘抄、会议记录              只读，不许改、不许删
work/       草稿、项目笔记                  可读可写，改动必须能回滚

出库前自问一句：这段进了云端模型的日志我能接受吗？不能就留在 private/。
```

资源：Cryptomator https://cryptomator.org/ · Meld Encrypt https://community.obsidian.md/plugins/meld-encrypt

## 97. 本地模型不是零成本，性能踩坑怎么自查与止损？

本地模型不是零成本，卡顿这件事得先分层定位，再决定换什么，别一上来就换模型、换量化、换后端瞎折腾。

按三步分层，半小时内能定位到人。第一步进安全模式关掉全部插件冷启动，还是慢，说明跟插件无关，去查库本身的文件数和大附件。第二步库正常就用二分法找插件，一轮只开一半，最多四轮锁死那一个。第三步插件和库都干净了，再单独在终端跑一次模型看 eval rate，这时候的数字才代表模型本身。脱离 Obsidian 单跑，16GB 机器跑 7B 模型资料实测在两位数区间，明显掉到区间外就说明问题在模型层，跟插件无关。

信号明确就该停手，一次问答等待超过 30 秒、跑模型时别的软件明显卡、为了跑通已经搭进去三小时以上，中两条就别硬撑。降级方案照抄：本地只留摘要和改写这类短任务，问答改走云端按量付费，还不够就先把 AI 插件全关掉，把 vault 本身用顺再说。库能用，比模型跑在本地重要。

```bash
# 第 1 步 分层：设置 → 关于 → 重启并停用所有插件，记一次冷启动秒数
find . -name "*.md" | wc -l
# 单库笔记数涨到上万量级，就该考虑拆库

find . -type f -size +50M -not -path "./.obsidian*" | head -20
# 体积过大的附件挪到库外用链接引用

# 第 2 步 二分法找插件：开一半 → 重启 → 还慢就在这一半里继续砍，最多 4 轮

# 第 3 步 单独量模型，脱离 Obsidian 跑
ollama run <你在用的模型> --verbose "用一句话概括什么是双链"
# 看 eval rate，明显低于同类硬件区间就是模型这层的问题，跟插件无关
```

```
# 止损线（中任意两条就停手）
1 一次问答等待超过 30 秒，且你已经降过一档
2 跑模型时其他软件明显卡，风扇长时间高转
3 为了跑通已经花掉 3 小时以上
4 内存压力常驻黄色或红色（活动监视器 / 任务管理器）

降级三步：本地只做摘要和改写 → 问答走云端按量付费 → 仍不顺就全关 AI 插件
```

## 98. 别让对话白聊，但为什么“全自动化”才是更大的坑？

全自动化才是更大的坑，自动化只许做搬运和归类，取舍和删除必须你点头。前面教你把对话收进 vault 是为了留痕，这一题补的是留手。

三个信号说明手放得太开：你说不出昨天 agent 动过哪三个文件；库里堆着七天以上你没读过的自动日报；agent 的权限里带删除。自动化最危险的是把取舍也交出去，整理归档这些体力活给它没问题，但哪些留哪些删一旦也让它决定，库就会越长越歪还无人察觉。护栏两条今天就能装上。第一条是 Git，把库变成可回滚的，它改坏了你拿得回来，每次更新 AI 插件前先备份它的 plugins 子目录，出事几十秒回滚。第二条是白名单，把"可自动、需确认、永不自动"写清楚，超出表格的动作一律人工点头。

每周花两分钟跑一次 `git log`，扫一眼它这周动过什么。你留的手越多，将来它基于你的积累答出来的东西才越有根。

```bash
# 给库装一个撤销键
cd /path/to/vault && git init && git add -A && git commit -m "baseline"
printf ".obsidian/workspace.json\n.obsidian/cache\n.trash/\n" >> .gitignore

# 每天收工提交一次
git add -A && git commit -m "daily $(date +%F)"

# 发现它改坏了：先看动了什么，确认无误再回滚单个文件
git log --oneline -10
git diff HEAD~1 --stat
git checkout HEAD~1 -- "路径/被改坏的文件.md"
```

依赖：Git 命令行，或 Obsidian Git 插件的自动备份

```
# 自动化白名单（超出这张表的动作，一律人工点头）
可自动：抓取、归档到收件箱、加时间戳、按标签移动、生成草稿
需确认：改写正文、合并笔记、改标题、批量替换
永不自动：删除文件、清空文件夹、覆盖已有正文、推送到公开仓库

每周一次：git log --oneline --since="7 days ago"
```

## 99. 第二大脑被神化，哪些承诺你千万别信？

第二大脑被神化，凡是承诺里带"自动""一劳永逸""不用自己记"的，一律打对折听。它是你的外接硬盘，你才是 CPU，位置摆正就不会失望。把它当外接硬盘用确实省事，可一旦指望它替你产出洞见，失望就注定了，思考这活它替不了，外包出去的只能是反思，退化的是你自己的脑子，别信那些"自动"的甜话。

已经被神化的信号有四个：这个月你一次都没主动从库里取用过东西；被问最近在想什么，只能现打开库查；库越来越漂亮，产出为零；图谱看着壮观，随便点一个节点，你说不出它和你手上的事有什么关系。

体检五问每月做一次，五分钟，答案写进当月笔记。取用率还能用命令粗算，近 30 天动过的笔记占比明显偏低，你的库正在变成死档案。它强在随查随取、跨年不丢，弱在不会自己产生洞见。承认这条边界，你就不会指望它替你长脑子，也不会因为它没做到而整个弃库。

```
# 第二大脑月度体检（每月 1 号，5 分钟，答案写进当月笔记）
1 这个月我主动从库里取用过几次？写下具体场景，少于 3 次说明只存不用
2 我这个月的产出里，有几处引用了半年前的旧笔记？0 就是死档案
3 新增笔记里，有几条写的是我自己的判断，不只是复制粘贴
4 有没有哪条笔记我至今一遍都没读过？有就先读，再谈新增
5 换个工具的话，我最舍不得的是哪 10 条？把它们标出来，那才是你的核心
```

```bash
# 取用率粗算：近 30 天动过的笔记 / 总笔记数
find . -name "*.md" -mtime -30 | wc -l
find . -name "*.md" | wc -l
# 比值明显偏低，说明库正在变成死档案，先做上面的体检五问
```

## 100. 用了一年才懂的 3 件事是什么？

用了一年才懂三件事：少即是多、AI 给草稿你做取舍、笔记是你的。每件都配一个今天就能做的动作。

第一，少即是多。官方自己都在降依赖、上安全记分卡，过不了审查的老插件迟早从目录里消失，你却在往库里堆第三方插件。做一次插件年检：装了没启用的直接删目录，启用中的逐个去 GitHub 看最近提交，长期没动（一年半载以上）的就找替代，弃更的插件才是后来莫名其妙崩掉库的那颗雷。

第二，AI 给草稿你做取舍。它列提纲、找素材都行，删哪句、留哪句、结论怎么下必须你自己来。每份 AI 草稿进库前问三句：这段的判断我认不认、里面有没有一句是我自己的话、删掉一半还剩下什么，答不出就别收。

第三，笔记是你的，这句话靠演练验证别停在信念上。每半年关掉 Obsidian，用纯文本编辑器打开五条笔记还读得懂，它就真的属于你；读不懂说明你被锁进插件了，回头把关键信息落回正文。

```bash
# 插件年检：对比"装了的"和"启用的"
ls .obsidian/plugins
python3 -c "import json;print(json.load(open('.obsidian/community-plugins.json')))"
# 装了没启用的：确认目录名无误后删掉
# 启用中的：逐个打开 GitHub 看最近提交，长期没动就找替代
```

```
# 退出演练（每半年一次，30 分钟）
1 关掉 Obsidian，用系统文件管理器打开 vault 文件夹
2 随便挑 5 条笔记，用纯文本编辑器打开，看还读不读得懂
3 命中任意一条，说明你已经被锁进插件：
   正文全是 dataview 之类的查询块，关掉插件就剩一片空白
   附件路径靠插件维护，脱离 Obsidian 图片全裂
   关键信息只存在插件的 data.json 里，没落进 md 正文
4 修法：常看的查询视图定期导出一份静态清单，正文坚持用标准 Markdown 写
```
