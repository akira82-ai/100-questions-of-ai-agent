# 第二章 · 日常笔记的实用打法：先会记，再谈 AI

这一章不讲 AI。先把记这件事讲透，AI 后面才有东西可读。

八百条笔记捞不出一条来，问题很少出在数量上。存下的多半是那种记完就贬值的东西，链接连得又密又没道理，同一个概念的标签有三种写法，附件散在库的各个角落。这些毛病单拎出来都不致命，攒到一起库就开始烂，烂的不在某条笔记写得差，在整张图的结构塌了。

接下来十六题，从怎么记、怎么连、怎么标、怎么命名，一路走到怎么把散在各处的旧库归拢回来。全是能照着做的动作。

## 15. 笔记记了八百条从不用，怎么记才算"用得上"？

记了不用，多半是因为你存的全是那种记完就贬值的东西。工具命令、概念解释、软件教程这一类，AI 三秒钟能列一份更全的，你攒八百条也不值钱。真正扛得住时间的是判断，什么时候该做、什么时候不该做、什么信号一出现就该换条路，这层 AI 学不走，实践次数越多它越值钱。

所以记法得换。每周挑一件事写下来，只回答一个问题，这星期我做的哪个判断 AI 做不出来。篇幅不用长，三百字就够，但必须是真实的决策过程，写清楚为什么当时选了 A 没选 B。一年攒下五十来条，这就是你的护城河。

还有一条更省力的。别指望排期复习，定点回看往往落不到实处，因为你那会儿压根不在需要它的状态里，等真需要的时候又想不起自己写过。管用的是每次用到一篇旧笔记，顺手往里补一点新东西，用一次补一次，比哪天下决心从头整理一遍靠谱得多。光记录事实和信息大多数时候只是囤积，笔记的收益来自你写它和回看它这两下。

## 16. 别人双链连得飞起，我连了却更乱，问题出在哪？

乱是因为你连的时候根本没关系可言，看见补全弹出来就顺手按了 Tab。把每篇笔记跟每篇笔记都做主题标注、都交叉连一遍，这是刚上手时最容易犯的冲动，也是最大的一个错。

连之前先确认关系存不存在。两篇之间真有来源、有延伸、属于同一个项目，或者一个支持另一个、一个反驳另一个，这才连。为了让关系图看着丰满而硬加的链，只会让你以后从任何一个节点跳出去都跳到不相干的地方。关系图本身也别太当真，笔记上千之后它带来的多是视觉震撼，日常真在用的还是搜索加反向链接。

补全插件没毛病，毛病在默认配置太敏感。把匹配策略调成前缀匹配，最小触发字数设成两到三个字，别打一个字就弹窗。笔记过百之后它才真好用，那时候你想连某个概念却记不清完整标题，它一提示就中。另外把别名字段用起来，同一个概念的几种叫法都写进 aliases，打两个方括号时同义词和相关说法也能被提示出来，这比硬连一堆链有用得多。

## 17. 什么是 MOC，为什么它比文件夹更适合 AI 时代？

MOC 是 Map of Content，一篇只做目录的笔记。它本身几乎不写正文，就把同主题的其他笔记按结构列出来，做成这个主题的入口。再建一篇 Home 列出所有 MOC，就成了地图的地图。

它比文件夹好用的地方在于，文件夹是严格层级，一篇笔记只能待在一个文件夹里，层级一深就在想法之间砌起墙。MOC 不移动文件，只把关系摆出来，同一篇可以同时挂在三张地图下面。库长到多大都不要紧，从任一主题的 MOC 出发都能定位，新笔记只要被某一张地图引用过就算有了归属。在关系图里 MOC 是高密度节点，天然的导航枢纽，AI 顺着它走比一层层翻文件夹省事。

想让它真转起来，得配一条纪律，每篇新笔记至少链回一张 MOC。做法是在新建笔记的模板里留一个空的 MoC 属性，建的时候顺手填上。地图里的清单也不用手抄，写一句 Dataview 查询，把所有反链到这张地图、自身又没有出链的笔记自动列出来就行。

可复制模板（直接复制使用）：

```
# Python 学习地图
## 基础
- [[变量与数据类型]]
- [[函数]]
## Web 框架
- [[FastAPI 入门]]
```

在 MOC 笔记里放这段查询，自动聚合反链：

```dataview
list from [[]] and !outgoing([[]])
sort file.name asc
```

资源：Dataview https://community.obsidian.md/plugins/dataview

## 18. 标签到底怎么打才不滥用？三个反例告诉你

三个反例摆这儿。头一个是同一个概念三种写法，advml、AdvML、advanced-machine-learning 各存一份，检索时谁也聚不到一块，等于白打。第二个是只用过一次的标签，打完再没第二篇挂上去，纯噪音。第三个是给每篇都打五六个，标签数量爆炸，同一个主题散在十几个词里。

打得住的标签只标类别。人、论文、演讲、概念、工具、项目，这种一眼能归类的东西适合做标签。学科领域和具体主题别往标签里塞，那是笔记该干的活。日期也别打成标签，那该交给文件名。也可以干脆把标签压到最低，只留给几个特定的 Dataview 查询用，别处一概不碰，这样反而干净。

已经泛滥了也能救。先挑近似重复的合并，大小写和连字符不一致的统一成一种写法，只出现过一次的直接删掉。标签少而准，你和 AI 才能用同一套词去检索，以后查所有读书笔记一句话就出来，不会因为词形对不上而扑空。

资源：Dataview https://community.obsidian.md/plugins/dataview

## 19. 模板（Templater）要不要学？先抄这 3 个就够

要，但学到会抄这一步就够了，模板引擎的原理压根不用懂。Templater 比核心的模板插件强在能自动填当前日期、笔记标题、星期几，甚至弹个选择框让你选一项。

先把配置做完。装好之后进设置，Templater 里的 Template folder location 填一个文件夹名，比如就叫模板，然后把模板文件都建在这个文件夹里。以后新建一篇笔记，按 Ctrl/Cmd+P 搜 Templater: Insert template，选中模板，内容自动填进去，日期那栏会被替换成今天。

抄三个就够用。一个日记模板，自动带上当天日期和星期，下面三栏留着今天发生了什么、今天学到了什么、明天要做什么。一个读书笔记模板，顶部是 frontmatter，正文固定一句话总结、核心观点、启发与行动、金句摘录。一个会议记录模板，参会人、议题、讨论与结论、行动项分开列。剩下的等需要了再加，同一种笔记反复出现了再做模板，同一个手工动作反复发生了再找插件，别为一个还没成型的习惯先背上维护成本。

可复制模板（直接复制使用）：

```
# <% tp.date.now("YYYY-MM-DD") %> 日记

> 今天是 <% tp.date.now("dddd") %>。

## 今天发生了什么

## 今天学到了什么

## 明天要做什么

- [ ]
```

资源：Templater https://community.obsidian.md/plugins/templater-obsidian

## 20. 一条笔记写多长最合适，写太长 AI 也读不动？

没有标准字数，看它讲一件事还是几件事。实操里大部分笔记会很短，几句话加一张图就完了，它存在的主要目的是被索引进库、能从别处链过来。真跟你手头工作相关的那几篇才值得写长，写成好几页也没关系。

一篇一个想法是最稳的默认值。概念卡片就照三段写，用大白话解释这是什么，给一个例子，再列几个关联概念链出去。能用简单的话讲清楚，说明你是真懂了，讲不清楚就回去再学一遍。写的时候必须用自己的话重述，照抄原文的那种笔记等于零。

也别走到另一个极端，给每个犄角旮旯的小概念都建一篇迷你笔记同样没必要。拿不准就先别纠结，等哪篇明显臃肿了再拆。库里结构已经立住的话，合并和拆分都很快，顺着反向链接把几个链接改一改就完事。粒度细的好处是 AI 读到时能精准引用，不会在一篇五千字的大杂烩里抓不住重点。

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 21. 怎么让双链变成 AI 能用的"知识图谱"而非噪音？

给链接标上类型，图谱才算图谱。普通双链只说明两篇有关系，说不清是什么关系；在 frontmatter 里写成 hasTopic、isA、subset、author、project 这样的字段，链接就带上了语义，AI 沿着走才知道自己在走什么。

层级也靠这个搭。主题笔记之间用 subset 串成一张有向图，一个主题可以同时是两个上级主题的子集，文件夹做不到这件事，层级标签也做不到，它们只能长成树。论文、演讲这类笔记用 hasTopic 挂到主题上，主题笔记的反向链接里自动就出现了它们，导航面板里也能一层层点下去。

连的密度得够。凡是你想在笔记里提到的概念，哪怕那篇还没建，也先用方括号括起来。零反链的笔记内容写得再好，在库里功能上等于隐形。库烂掉这事很少是某条笔记写得差，多半是图结构出了问题，孤儿笔记、断链、只用过一次的标签攒到一定量，检索就开始失灵。顺带说一句，找相似笔记做链接建议这种活，关键词匹配就够了，不必什么都往语义模型上套。

可复制模板（直接复制使用）：

```
---
aliases: [同义叫法1, 同义叫法2]
hasTopic: "[[所属主题]]"
isA: "[[上级概念]]"
project: "[[相关项目]]"
---
```

主题笔记之间用 subset 建层级：

```
---
subset: "[[上级主题]]"
---
```

资源：Obsidian 帮助文档 https://help.obsidian.md/

## 22. 每天流水账式记录，怎么避免变成垃圾堆？

给日记派个活，让它当枢纽。日记的文件名就是日期，把它设成每天的起始页，一天里冒出来的东西先往这儿写，自己问自己的问题、临时查到的片段、还没成型的想法，都先堆在当天这篇里，将来哪条长大了再拆成独立笔记。

变枢纽的关键动作是把日期写成链接。写流程步骤、约会、通话记录、见过的谁、去过的哪儿，凡带日期的都用方括号括起来，链回那天的日记。这样当天那篇就自动汇总了跟这天有关的所有东西，反向链接一列，脉络自己就出来了。再给日记加个别名，除了 2026-05-21 这种编号，多写一句当天的主题词，以后靠这句话就能搜回来。

实在不知道往哪写的，单独建一篇草稿箱，专收那些不知道归属、也不确定要不要写完的东西。碎片捕捉的摩擦力也要压到最低，配一个捕捉类插件，按快捷键弹输入框，打字回车就追加到指定笔记，整个过程不超过三秒。流水账本身没毛病，毛病在记完扔那儿不管。

资源：QuickAdd https://community.obsidian.md/plugins/quickadd

## 23. 读书/看文章怎么记，才不是"复制粘贴即吃灰"？

原封不动复制粘贴等于零，这条得先认。摘一整段进来，它只是换了个地方躺着，你以后既想不起它讲什么，也想不起当初为什么存它。

一篇以后还能复用的笔记至少得有四块。这是什么，用你自己的话概括一遍；我的判断，为什么它值得留下；下一步，准备拿它做什么；相关内容，链到哪些项目或主题上去。第四块尤其别省，在相关内容里写上主题页的双链，以后从这篇能点进主题页，主题页的反向链接里也能重新看到它。

读书笔记就固定一套结构去填。顶上放 frontmatter 记书名、作者、评分、读完日期，正文分一句话总结、核心观点、启发与行动、金句摘录四栏。这套结构真正的作用是逼你写出那句自己的话，写不出来说明还没读懂。零散的文章收藏也一样，每条底下缀一句为什么值得看，不写理由的收藏以后一次都不会再打开。

```

tags: 读书笔记
书名:
作者:
评分:
读完日期:
---
## 一句话总结
## 核心观点
## 启发与行动
## 金句摘录
```

## 24. frontmatter（YAML 头）有什么用，为什么 AI 特别吃这套？

frontmatter 是笔记最顶部用三个减号包起来的一组字段，作用是让机器能筛。人打开笔记先看到时间、状态、来源和摘要；搜索、插件、拿到访问权限的 AI 看到的则是一组统一的键值，能按字段精确过滤，不用在全文里猜。

字段贵精不贵多。先固定四个真会用到的就行，updated 记最后更新时间，status 记状态，summary 一句话说明这篇解决什么问题，source 写原始来源或链接，再加上 tags 和 created 也可以。字段一多就没人维护，最后半数笔记留着一堆空壳，反倒不如没有。

有了这层结构，Dataview 才有东西可查。给读书笔记统一写上书名、作者、评分、读完日期，然后在任意一篇里写一句查询，一张按读完日期排序的表就自动出来了，以后每加一篇它自己更新。反过来，字段名对不齐、类型忽字符串忽数字、有的笔记有有的没有，这些都是库开始烂掉的信号，早点拿检查工具扫一遍比事后补强。

可复制模板（直接复制使用）：

```
---
updated: 2026-05-21
status: active
summary: 这篇笔记主要解决什么问题
source: 原始来源或链接
tags: 读书笔记
书名:
作者:
评分:
读完日期:
---
```

配套查询，放在任意一篇笔记里：

```dataview
TABLE 作者, 评分, 读完日期
FROM #读书笔记
SORT 读完日期 DESC
```

资源：Dataview https://community.obsidian.md/plugins/dataview

## 25. 用 AI 帮我写笔记，会不会反而让我不动脑？

会，所以别把正文交给它写。记笔记这件事的全部意义就在于用自己的话写一遍，然后回头看看当时到底理解到了什么程度，这一步被代掉，笔记就白记了。

从学习的角度讲，真带来收获的是那些逼你在脑子里加工的外部动作，把新信息跟已有的知识挂上钩就是最典型的一种。风险从来不在模型有多强，而在你拿它当绕开这段加工的捷径，跟学生让 AI 代写作业最后写作能力退化是同一个机制。

划一条线就行。问答、查资料、写代码、辅助润色，这些照用不误；库里那些代表你理解的笔记，正文自己写。AI 给的东西一律当草稿看，你用自己的话改一遍、顺手连一条相关的旧笔记，它才算真进了你的库。它擅长的是在你授权之后，在这批资料里检索、整理、接着往下干活。让它替你写，别让它替你想。

## 26. 会议/访谈记录怎么存，以后 AI 才查得到？

先别急着全存。会议记录时效性很强，多数只在几周内有用，而且它最大的价值在于分享给别人看，Obsidian 是单人工具，markdown 传来传去挺别扭。整场逐字记进库，几个月后这些东西只会稀释你的库。

真该留下的是结论和行动项。标题写成日期加会议主题，比如 2026-05-21 产品需求评审，正文分参会人、议题、讨论与结论、行动项四块，只记结论、决定和谁要干什么，不记每句发言。行动项写成任务行，后面缀上截止日期，这样在别的笔记里写一个查询块，就能把全库未完成、明天前到期的任务全捞出来。建一篇任务总览专门放几个不同条件的查询，每天打开它就够了。

要是这场会跟某个项目绑得死，索性把行动项直接挂进项目笔记，不单独建文件。还有一条护栏，公司的事留在公司的工具里，你自己的复盘、判断、对这件事的看法才往 Obsidian 放，换个东家的时候不至于把积累一起交出去。

可复制模板（直接复制使用）：

```
## 参会人
## 议题
## 讨论与结论
## 行动项
- [ ] 谁做什么事 📅 2026-05-22
- [ ] 谁做什么事 ⏳ 2026-05-25
```

任务总览笔记里放这段查询：

~~~
```tasks
not done
due before tomorrow
```
~~~

## 27. 图片、截图、PDF 怎么进 vault 才不脱节？

先把附件路径设死。进设置里的文件与链接，附件默认存放路径指一个文件夹，粘贴和拖进来的图片、PDF 全部统一落到那儿，不然它们会散在库的各个角落。想再细一点，可以让附件跟着笔记走，新附件位置填成 ./assets/${noteFileName}，附件文件名按时间戳生成，再把改名时同步处理打开，笔记改名附件目录跟着改，引用就不会断。

PDF 直接拖进编辑区就入库并生成链接，在文件列表里双击能翻页阅读，想嵌进正文就用感叹号加双方括号引用文件名。音频视频同理，mp3、wav、m4a、mp4、webm 这些丢进去，阅读模式下直接出播放器。视频得节制，大文件会让仓库膨胀、同步变慢，小的放进来，大的存网盘、库里只记链接。笔记里常贴截图的话，装个图片工具箱类插件，点开能全屏、滚轮缩放、左右键切换、Esc 关掉，装完即用不用配置。

不脱节的关键还是那一句话。每张图、每个 PDF 旁边写一句它讲什么、跟哪篇有关，再用双链接回去，光丢进附件文件夹等于没存。整批从 Word、Notion、EverNote 搬过来的资料用 Importer 导，原结构和链接都能保住。

资源：Importer https://community.obsidian.md/plugins/importer · Image Toolkit https://community.obsidian.md/plugins/image-toolkit

## 28. 命名和目录有什么笨办法但最稳？

数字前缀加两级封顶，就这两条。前缀让排序固定下来，00 收件箱、01 日记、03 项目，系统按数字排，你不用记顺序，也不会被首字母打乱。文件夹最多一到两级，再深就靠 MOC 和双链去串，别建一堆嵌套。

一级目录别照抄别人的体系，按你真实会处理的内容建少量几个就行。做内容的可能需要选题和发布，做项目的可能更需要进行中和已完成，目录是跟着实际工作长出来的，不是先复制一套知识管理体系再往里塞。拿不准的笔记先扔收件箱，定期清一次。

常用的那几个文件夹，可以在最前面放一篇 00 Index，写清楚这里有什么、重要内容从哪儿进、眼下最常打开的是哪几篇；再放一篇 00 Rules，写什么内容该放进来、文件怎么命名、按时间还是按重要程度排、完成之后挪去哪儿。文件夹简单的话，规则直接写进 Index 就行，别为了形式硬建两个空文件。排序逻辑在同一个文件夹里只用一种，按时间就都按时间，按重要程度就都按重要程度，混着来最后谁也找不着。

可复制模板（直接复制使用）：

```
我的仓库/
├── 00-收件箱/      # 临时素材，待整理
├── 01-日记/        # 自动按 YYYY-MM-DD 命名
├── 02-周记/        # YYYY-Www
├── 03-项目/        # PARA 的 Projects
├── 04-领域/        # PARA 的 Areas
├── 05-资源/        # PARA 的 Resources
│   ├── 读书笔记/
│   ├── 知识卡片/
│   └── 学习/
├── 06-归档/        # PARA 的 Archives
├── 99-附件/        # 图片、PDF 等
└── 模板/           # 各类笔记模板
```

## 29. 日记到底记什么，才能成为 AI 未来的"上下文"？

三栏加一句判断。今天做了什么、今天学到了什么、明天要做什么，这三栏是骨架；真正让日记以后有用的是第四样，当天你做了什么判断、为什么这么定。前三栏 AI 读得懂事实，第四样才是它学不走的那部分。

节奏靠工具兜住。把核心插件里的日记打开，再装一个日历面板钉在右侧栏，哪天写了哪天空着一眼看得见，点日期直接跳过去或者新建。往上一层用周期笔记补齐周记、月记、季记、年记，周记的格式设成 YYYY-[W]ww，指定好模板和文件夹，在日历上点周数就能创建当周那篇。

每周留一次复盘。周日花十五到二十分钟写四块，这周完成了什么、这周最大收获、哪里做得不好、下周最重要的三件事。后两块是重点，前两块顺手就写完了，难的是承认哪儿做砸了，以及把下周收敛到三件。坚持一个月回头看，你会发现自己做的事比记忆里多得多。这些真实记录攒起来，AI 以后读你的库，能从时间线上把你拼出来。

可复制模板（直接复制使用）：

```
## 今天做了什么
## 今天学到了什么
## 明天要做什么
- [ ]
## 今天的判断
- 定了什么 / 为什么这么定
```

周复盘模板：

```
## 这周完成了什么
## 这周最大收获
## 哪里做得不好
## 下周最重要的 3 件事
1.
2.
3.
```

## 30. 我的笔记太散，AI 回答时东拼西凑怎么办？

先立一个单一入口。细节可以还留在原来的地方，但库里得有一篇指过去的索引笔记，你在一个地方就能看全所有关联。批量的资料用 Importer 从 Word、Notion、EverNote 导进来，飞书这类先导出 Markdown 再拖进仓库。导完先整批扔进归档，桌面立刻就干净了，历史一条没丢。

然后别急着整体重建。给所有旧笔记补齐属性和标签这种活，干几天就再也不想打开了。只处理最近真用到过的那些，还会继续用的留下并补一句摘要，内容重复的合并成一篇主笔记，失效但要留档的挪进归档，暂时不知道怎么办的先别动。同一主题攒够几篇了，再建一张索引把它们连起来。

心态上要认这个账，八成成功就算赢。先把一个能长期用下去的结构定下来，新建的笔记一律走新结构，旧的一次消化一点，力气花在你真能受益的地方。给旧笔记加一个状态字段，碰一次升一档，从待处理到能用再到成熟，整理这件事就从一场大工程变成了顺手的动作。等入口、字段、地图这三样都立住，AI 回答时才是顺着一张图在走。

可复制模板（直接复制使用）：

```
迁移期给每篇旧笔记加一个状态字段：

---
status: seed        # seed → sapling → evergreen
source: 原始来源
updated: 2026-05-21
---

归档策略：

06-归档/          # 旧库整批先进这里，历史不丢
00-收件箱/        # 用到时从归档捞出来，处理完移到正式位置
```
